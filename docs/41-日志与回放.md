# 41 · 日志与回放（M5）

> 真机出问题时，"刚才那一秒电压掉到多少、几号舵机报故障"比任何解释都值钱。
> 这一层只做记录和汇总，不猜原因。

## 1. 记录

```bash
modkit --sim record --ids 1,2,3 --seconds 3 --hz 5 --out telemetry.csv
```

CSV 字段：

| 字段 | 含义 |
|---|---|
| `t` | 相对开始的秒数 |
| `sid` | 舵机 ID |
| `pos_deg` | 位置（度） |
| `speed` | 反馈速度（原始值） |
| `load` | 负载（原始值） |
| `voltage` | 电压（V） |
| `temp_c` | 温度（℃） |
| `status` | 0x41 状态位 |

固定频率读取，不插值；掉帧就是掉帧，宁可少一条也不补假数据。

## 2. 回放

```bash
modkit replay --log telemetry.csv
```

输出：

```json
{
  "n": 9,
  "seconds": 0.6,
  "ids": [1, 2, 3],
  "v_min": 12.0,
  "v_max": 12.0,
  "t_max": 32,
  "faults": 0,
  "v_end": 12.0
}
```

末电压按 3S 锂电粗估：12.6V=100%，9.9V=0%，<10.8V 提示 low，<10.2V 提示 critical。
**只用于提示，不用于保护**——保护在固件里做。

## 3. 实测

| 项 | 结果 |
|---|---|
| 仿真记录 0.6s @5Hz ×3 舵机 | 9 条 |
| 0.4s @10Hz ×3 | 12 条 |
| CSV 往返 | 字段/数值一致 |
| 汇总 | 电压 12.0–12.0V、32℃、0 故障 |
| 电量 | 12.0V≈78%（ok）、10.5V（low）、10.0V（critical） |

6 项测试，`tests/test_telemetry.py`。

## 4. 还没做的

- **画图**：现在只输出汇总 JSON；要看曲线用 pandas/matplotlib 读 CSV；
- **事件标记**：没有"第 12 秒按了急停"这类人工标记；
- **自动诊断**：不做规则引擎，避免误报；
- **长时间滚存**：没有分段/压缩，30min × 6 舵机 @10Hz 约 10 万行，CSV 够用但不适合几个月。

这些都不阻塞装机；真机跑起来后按需要再加。
