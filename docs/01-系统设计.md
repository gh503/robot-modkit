# 01 · 系统设计

> 这份文件回答一个问题：**为什么是这些零件、这些接口、这些数据流**。
> 具体尺寸看 `cad/params.py`，具体接线看 [03-配电与线束](03-配电与线束.md)。

## 1. 整机形态

```
                     ┌──────────┐
                     │  夹爪    │  ← 舵机 4（开合）
                     └────┬─────┘
                  腕 ┌────┴─────┐
                     │  肘关节  │  ← 舵机 3（pitch）
                     └────┬─────┘
                  上臂│ 120mm
                     ┌────┴─────┐
                     │  肩关节  │  ← 舵机 2（pitch）
                     └────┬─────┘
                  立柱│ 90mm
                  ┌──────┴───────┐
                  │  底座偏航    │  ← 舵机 1（yaw）
                  └──────┬───────┘
   ┌─────────────────────┴─────────────────────┐
   │ 底盘：2 驱动轮（舵机 5/6，恒速模式）        │
   │       + 2 万向球轮 + 电池 + 主控 + 相机     │
   └───────────────────────────────────────────┘
```

- 4 个关节 + 2 个驱动轮 = **6 个总线舵机，一条链**。这是"模块化"最直接的证据：
  **驱动轮和关节是同一种零件**。
- 轮径 65mm，轮距 150mm，底盘 240×200mm，整机高约 420mm，重约 2.2kg。
- 臂展 230mm，工作半径 40–230mm，可抓 0–250mm 高度。

## 2. 坐标系与标定基准（先定，再画图）

| 坐标系 | 原点 | 轴向 | 用途 |
|---|---|---|---|
| `base_link` | 底盘中心地面投影 | x 前、y 左、z 上 | 底盘运动、里程计 |
| `arm_base` | 偏航轴与底盘上表面交点 | 同 base_link | 臂的逆解 |
| `camera_link` | 相机光心 | z 前方、x 右、y 下 | 视觉（注意：ROS 光学坐标系） |

- 遵循 ROS REP-103（右手系）、REP-105（map/odom/base_link 约定）——
  即使现在不用 ROS，也照这个约定，将来接 nav2 不用改符号。
- 单位：**内部一律 mm**，对外接口（CLI/JSON）用 mm 与度。ROS 层再乘 0.001。

## 3. 电气架构

```
 3S 锂电 (11.1V)  ── XT60 ── 主开关 ── 8A 保险 ──┬── 舵机母线（6×2A 分支保险）
   或 12V/5A 适配器                              │
                                                 ├── 降压 5V/3A ── 树莓派/ESP32
                                                 └── 1000µF 电解 ── GND
 总线：ESP32 (UART1, 1Mbps, DIR 脚) ── 菊花链 ── 舵机1..6
 感知：USB 相机 ── 树莓派
 通信：ESP32 ⇄ 树莓派（USB 串口，自定义帧或 micro-ROS）
```

**为什么 ESP32 + 树莓派双控**

| 需求 | ESP32 | 树莓派 |
|---|---|---|
| 1Mbps 总线时序、DIR 切换 | ✅ 硬实时 | ❌ Linux 抖 |
| 视觉、导航、任务逻辑 | ❌ | ✅ |
| 断电/重启影响 | 小 | 大 |

分工：**ESP32 只管"按时序把字节发出去、把反馈读回来"**；树莓派只管"决定去哪、抓什么"。
两者用一帧一应答的串口协议，ESP32 侧加看门狗：**200ms 收不到心跳就卸力**（防止树莓派死机时机器人还在动）。

## 4. 软件分层

```
┌───────────────────────────────┐
│ 任务层  task_executor          │  T1 状态机：IDLE→NAV→SEEK→GRASP→DELIVER→HOME
├───────────────────────────────┤
│ 应用层  nav / vision / grasp   │  路径规划、方块检测、抓取姿态
├───────────────────────────────┤
│ 运动层  kinematics / odometry  │  逆解、里程计、速度指令        ← 已有（software/）
├───────────────────────────────┤
│ 驱动层  Robot / ScsBus         │  扫描、读反馈、同步写          ← 已有
├───────────────────────────────┤
│ 链路层  SerialLink / SimLink   │  串口 / 仿真                   ← 已有
├───────────────────────────────┤
│ 固件    ESP32 + FT-SCS         │  实时总线                      ← 已有
└───────────────────────────────┘
```

**关键设计：`SimLink` 与 `SerialLink` 接口一致**。所以任务层可以在完全没硬件时开发、
在有硬件时一行不改地切换。这是本项目"能落地"的核心手段。

### 4.1 为什么先不套 ROS 2

ROS 2 Humble 装在这台机器上（`/opt/ros/humble`），但**M1–M2 阶段不引入**：

- ROS 的价值在"多节点、多传感器、标准消息"，你现在只有 1 个串口和 1 个相机；
- 引入后调试链路变成"launch → 节点 → DDS → 话题"，新手排障成本翻倍；
- **M4 才需要 nav2/slam_toolbox**，那时再套一层 `ros2_control` 或直接发 `/cmd_vel`。

迁移路径已经留好：坐标系、单位、速度指令语义都按 ROS 约定写，接的时候加一个 20 行的 bridge 节点。

## 5. 数据流（任务 T1）

```
相机 30fps ─→ 检测(颜色+轮廓) ─→ 像素坐标
                                   │ 手眼标定矩阵
                                   ▼
                            base_link 下的目标位姿
                                   │
   里程计 ──→ 当前位姿 ──→ 导航控制器 ──→ (v, ω) ──→ 轮速 ──→ 舵机5/6
                                   │
                                   ▼
                          逆解 ──→ 关节角 ──→ 同步写 ──→ 舵机1–3
                                   │
                                   ▼
                          夹爪开合 ──→ 舵机4
```

### 5.1 时序预算（决定"看起来顺不顺"）

| 环节 | 预算 | 说明 |
|---|---|---|
| 相机采集 + 检测 | 60ms | 15fps 足够，别追 60fps |
| 导航控制周期 | 50ms | 20Hz，够了 |
| 臂同步写 | 3ms | 一条帧改 4 个关节 |
| 读 6 个舵机反馈 | 12ms | 6×2ms 往返 |
| 端到端（看到→动） | < 150ms | 超了就会"犹豫" |

**串口是瓶颈**：1Mbps ≈ 100KB/s，一次 6 关节同步写 42 字节 ≈ 0.4ms，但往返等待占大头。
所以固件里要支持**异步读**（发完不等，下一周期取结果）。

## 6. 安全设计（不是可选项）

| 层级 | 措施 | 触发 |
|---|---|---|
| 硬件 | 主开关、8A 保险、每路 2A 自恢复保险 | 短路/过流 |
| 电气 | 1000µF 抗尖峰、SS34 防反接 | 上电瞬间 |
| 固件 | 转矩上限 60%、保护电流 2.5A、加速度限制 | 堵转 |
| 固件 | 心跳看门狗 200ms → 卸力 | 上位机死机 |
| 软件 | 软限位（角度、工作空间） | 越界指令 |
| 软件 | 急停：`Ctrl+C` 也要卸力（`finally` 里写） | 人为 |
| 机械 | 关节机械限位（打印件凸台） | 失控 |

**急停语义**：不是"停止发送指令"，而是**主动写 0x28=0（卸力）**。
舵机卸力后可以被手推动，这是安全的默认态。

## 7. 可维护性设计

| 设计 | 目的 |
|---|---|
| 全部连接用 20mm 网格 + M3 | 一把内六角拆全机 |
| 每个舵机独立 2A 保险 | 坏一个不拖累全链 |
| 总线菊花链，插头防呆 | 换件不用记线序 |
| 舵机 ID 贴标签 + 固件配置表 | 换件只改一个数字 |
| `params.py` 单一尺寸源 | 改一处，全零件联动 |
| 日志 + 回放 | 失败可复现 |
