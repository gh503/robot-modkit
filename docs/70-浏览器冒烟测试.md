# 70 · 浏览器冒烟测试（Chrome + CDP）

> 状态：**v1.23.0 已实现**。入口：`make web-smoke` / `bash tools/web-smoke.sh`。
> 不需要 Python 测试依赖，不需要 Playwright；用本机 Chrome/Chromium 的 DevTools Protocol。

## 70.1 为什么需要

pytest 能验证 Python、JSON 和静态 hooks，但验证不了：

- 设计器在真实浏览器里是否初始化、7 个预设是否都能求解；
- 选中的组件是否真的出现 3D 包围盒；
- 复制/粘贴/拖拽导入是否真的改动了装配；
- `view.html` 的 3D 是否真的画出三角形、关节滑杆/播放/爆炸是否工作；
- `index.html#d=` 是否真的重定向；
- Service Worker 是否真的激活并缓存壳。

这些是 v1.15–v1.17 实际踩过的回归点（旧 JS、offboard 预设、分享快照、查看器静态）。
所以把它们放进 CI，而不是发布前人工点。

## 70.2 组成

| 文件 | 作用 |
|---|---|
| `tools/web-smoke.sh` | 起临时静态服务器 + 无头 Chrome，设置 CDP 端口，跑完清理 |
| `tools/web-smoke.mjs` | Node 22 原生 `WebSocket`/`fetch`，逐项 CDP 断言 |
| `.github/workflows/ci.yml` `web-smoke` job | PR/push 自动跑；Chrome 由 runner 提供 |

不引入 npm 依赖，也不把 Chrome 变成 `make check` 的硬依赖：
本地没有 Chrome 时只跳过 `web-smoke`，不影响 282 项 pytest。

## 70.3 覆盖项（8 组）

1. Studio 初始化、7 个预设与下拉。
2. 逐个预设求解：实例数、BOM、0 错误、`sensor_tower` 的 offboard。
3. 3D 选中包围盒、问题实例高亮（载荷超限）、复制/粘贴、撤销、拖拽 JSON 导入。
4. 导出 GLB/3MF/打印页：GLB 头、ZIP 头、BOM/TOTAL。
5. 项目保存/版本快照/恢复/旧 schema 迁移。
6. Pareto/约束：候选徽标、minJoints=4 规划、maxMass 不可行、约束 UI。
7. 网格碰撞：盒相交/分离/包含；m1 三个关节力矩、力矩表 3 行。
8. Studio 生成 `view.html#d=...`，长度 < 60000。
9. 查看器：18 组、三角形 > 500、4 个滑杆、2 个驱动轮、1 个夹爪；爆炸/播放/复位。
10. `index.html#d=` 重定向到查看器。
11. 无效分享链接显示“无法显示”。
12. 移动/无障碍/i18n：切 EN/中、导航/播放/placeholder/标题、标注 ≥20。
13. Service Worker 激活 + `modkit-shell-*` + STEP 预缓存 + manifest 图标；全程无页面脚本异常。

## 70.4 运行

```bash
make web-smoke
# 或指定端口（避免占用）：
MODKIT_WEB_PORT=8788 MODKIT_CDP_PORT=9233 bash tools/web-smoke.sh
```

输出：

```text
- Studio 打开且 7 个预设 ... ok
- 逐个预设求解 ... ok
- 3D 选中/复制粘贴/拖拽导入 ... ok
- 查看器渲染 + 关节/爆炸 ... ok
...
web smoke: PASS（13 项）
```

## 70.5 边界

- 这是**冒烟**，不是视觉回归：断言 DOM/状态/三角形数，不比较像素。
- 3D 使用 SwiftShader（CI 无 GPU）；只证明能画，不证明真实渲染质量。
- 不覆盖 Web Serial 真机、物理碰撞、动力学；那些仍需硬件/专门测试。
- 物理闸门仍是 **0/5**。
