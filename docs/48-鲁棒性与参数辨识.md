# 48 · 鲁棒性与参数辨识

> 一次通过不算数：随机扰动 30 次看分布；仿真参数也不能拍脑袋，从真机日志反推。

## 1. 蒙特卡洛：`modkit simsweep`

```bash
modkit simsweep --scenario sim/scenarios/nav_square.json -n 30 --profile clean
modkit simsweep --scenario sim/scenarios/nav_square.json -n 30 --profile harsh --out sweep.json
```

每个样本随机扰动：打滑、电池 OCV、负载、丢帧率、舵机额定力矩；种子固定，
同种子结果逐位一致。链路层默认 3 次重试，不让丢帧直接毁掉整批。

| profile | 打滑 | OCV | 负载 | 丢帧 | 力矩 |
|---|---|---|---|---|---|
| `clean` | 0 | 12.0–12.4 | 0 | 0 | 2.8–2.94 |
| `mild` | 0–3% | 11.6–12.4 | 0–0.1kg | 0–1% | 2.6–2.94 |
| `harsh` | 0–30% | 10.2–12.4 | 0–0.3kg | 0–8% | 1.8–2.94 |

输出：通过率、终点误差 p50/p95/max、每个失败样本的参数与原因。
`--min-pass 0.9` 时低于阈值退出码 1，可直接进 CI。

**已知结论**：`clean` 下方形 100% 通过；纯里程计对打滑很敏感，mild/harsh 的
通过率会明显下降——这正是 `nav_square_localized`（相机标记）存在的理由。

## 2. 参数辨识：`modkit identify`

```bash
modkit identify --log telemetry.csv --json params.json
```

从 `modkit record` 的 CSV 反推两个量：

| 量 | 方法 | 输出 |
|---|---|---|
| 编码器刻度 | 位置差分 vs 反馈 speed，过原点回归 | deg/LSB + R² |
| 电池 OCV/内阻 | `V = OCV − R·(I+idle)`，`I = load·4.5/1000` | V、Ω + R² |

合成数据验证（`synthetic_samples`）：

```
编码器：0.08789 deg/LSB（R² 1.000）
  理论值 360/4096 = 0.08789；偏差 -0.00%
电池：OCV≈12.20V，内阻≈0.121Ω（R² 0.999）
```

### 边界

- `load → 电流` 用 4.5A 满量程假设；真机要用电流表标一次；
- 电压采样只有 0.1V 分辨率，内阻辨识需要足够的负载变化；
- 摩擦、回差、死区**不从这份日志算**（没有激励信号），要专用标定；
- 打滑会让编码器刻度偏大，先确认轮子没打滑再采数。
