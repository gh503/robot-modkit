# 07 · 小白操作手册（从零到任务闭环）

> 这份手册假设你：**会装软件、会看命令行输出，但没焊过板、没建过模、没写过嵌入式。**
> 每一步都给"做什么 → 命令 → 应该看到什么 → 不对怎么办"。
> 卡住时先查 [09-故障排查](09-故障排查.md)，再回来。

---

## 第 0 步 · 安全（先读，5 分钟）

| 风险 | 规矩 |
|---|---|
| 舵机堵转发热 | 手挡输出超过 2 秒就松开；外壳烫手（>60℃）立即断电 |
| 夹爪夹手 | 调试时**手不进夹爪行程**；夹爪力虽小，但齿轮会咬 |
| 锂电池 | 只用带 BMS 的成品电池；**不要**短接、不要摔、鼓包立即停用 |
| 烙铁 | 热熔铜螺母 250℃；烙铁放支架，线不要跨过桌面 |
| 上电瞬间 | 第一次上电**不要碰机器人**，站在侧面，手放主开关上 |
| 急停 | 任何时候按主开关断电；软件急停是 `Ctrl+C`（会在退出时自动卸力） |

**唯一的安全默认态：舵机卸力（写 0x28=0）。** 机器人不动 = 安全。

## 第 1 步 · 电脑环境（30 分钟）

### 1.1 装基础软件

```bash
# Ubuntu（本项目在 Ubuntu 22.04 上验证过）
sudo apt update && sudo apt install -y git python3-venv python3-pip

# 检查版本（要 3.10+）
python3 -V
```

Windows 用户：装 [Python 3.11+](https://www.python.org/downloads/) 时勾选 "Add to PATH"，
后面命令里的 `python3` 换成 `python`，路径换成 `COM3` 之类。

### 1.2 拿到项目并装依赖

```bash
git clone <你的仓库地址> robot-modkit
cd robot-modkit
python3 -m venv .venv
./.venv/bin/pip install -e software
```

### 1.3 先跑"没有硬件"的版本（**这一步必须成功再往下**）

```bash
./.venv/bin/python -m modkit.cli --sim scan
```

应该看到：

```
扫描 0..20，用时 0ms
找到 6 个： [1, 2, 3, 4, 5, 6]
  ID 1:  180.0°  12.0V  32℃
  ...
```

再试逆解：

```bash
./.venv/bin/python -m modkit.cli --sim pose --x 150 --y 0 --z 150
# 逆解：偏航 0.0°  肩 -21.1°  肘 -90.8°
```

> **为什么先跑仿真**：证明你的 Python 环境、代码、命令都对。这样后面真机不通时，
> 你可以确定"不是软件装错了"。

### 1.4 装切片软件（打零件用）

任选：Bambu Studio / OrcaSlicer / PrusaSlicer。没有打印机就跳过，用淘宝代打（发 STL 即可）。

## 第 2 步 · 下单与验货（M0，¥800）

按 [04-BOM](04-BOM.md) 下单。**最关键的一条：舵机型号后缀必须是 C018（12V 版）。**

到货后做 **G0 来料检验**（[06-调试与测试](06-调试与测试.md)），核心是三把卡尺测量：

| 量什么 | 记到哪 | 为什么 |
|---|---|---|
| 机身 45.2 × 24.7 × 35 | `cad/params.py` 的 `SERVO_L/W/H` | 手册值可能有偏差 |
| 花键外径（应 5.9） | `SERVO_SPLINE_OD` | 决定输出盘孔径 |
| **花键露出高度** | `SERVO_SPLINE_H`（当前假设 2.0） | 决定输出盘能不能咬住 |

改完跑一次：

```bash
cd cad && ../.venv/bin/python build.py     # 必须 33/33 PASS
```

> 如果 `花键插座深度 > 花键露出高度` 这条变红了，说明实物花键比设计的深，
> 把 `SERVO_SPLINE_H` 改成实测值即可 —— **这就是参数化建模的意义**。

## 第 3 步 · 打印与装第一个关节（M0，2 小时）

### 3.1 打印

```bash
cd cad && ../.venv/bin/python build.py     # 生成 cad/out/*.stl
```

把 `cad/out/` 里的 5 个 STL 丢进切片软件。参数：

| 参数 | 值 | 原因 |
|---|---|---|
| 材料 | PETG | 韧性好，不会像 PLA 那样脆断 |
| 层高 | 0.2mm | 精度/速度平衡 |
| 壁数 | 4 | 螺钉受力处靠壁，不靠填充 |
| 填充 | 30–40% | |
| 支撑 | 仅底板角柱下方需要 | 其余悬空 ≤ 45° |
| 方向 | 底板平放，孔轴垂直 | 孔才不会塌 |

### 3.2 装（详细步骤见 [05-装配手册](05-装配手册.md)）

四步：**过孔 → 熔铜螺母 → 舵机入槽 → 输出盘 + 盖板**。

验收动作（拿秒表）：

- [ ] 拆一个关节 < 90 秒
- [ ] 输出盘手转能带动舵机轴，无打滑
- [ ] 盖板与舵机之间能塞进 0.3mm 纸片（说明有间隙，不是硬压）

## 第 4 步 · 第一次通电（最紧张的一步）

### 4.1 接线（先断电！）

```
12V 适配器 ──┬── 舵机 V+（红）
             ├── 舵机 GND（黑）
             └── 主控 5V 降压

USB-TTL 调试板：
   TX ── 1kΩ ──┬── 舵机 DATA（白/黄）
   RX ────────┘
   GND ──────── 舵机 GND（必须共地！）
```

⚠️ 三个最容易烧/不通的错误：**不共地**、**DATA 接到 V+**、**12V 接到主控**。

### 4.2 上电顺序（不能反）

```
1. 插 12V（等 2 秒，听舵机有没有"嘀"一声）
2. 插 USB（电脑识别串口）
3. 跑 scan
```

### 4.3 扫描

```bash
ls /dev/ttyUSB*            # 确认串口存在
./.venv/bin/python -m modkit.cli --port /dev/ttyUSB0 scan
```

看到 `找到 1 个： [1]` = **成功**。看到"没有找到舵机"就按 [09-故障排查](09-故障排查.md) 的"扫描不到"表逐条查。

### 4.4 让它动

```bash
./.venv/bin/python -m modkit.cli --port /dev/ttyUSB0 home
./.venv/bin/python -m modkit.cli --port /dev/ttyUSB0 read --id 1
```

- `home` 会让它回 180°。如果**方向反了**（往机械限位撞），立刻断电，改 `params.py` 里的方向或固件 `方向位`。
- 手轻轻挡住输出，观察 `读回负载` 是否上升 → 说明有力反馈，正常。

## 第 5 步 · 装整机（M1，3 周）

顺序很重要：**先臂后底盘，先单关节后整机**。

1. 装肩关节模块 → 单独测试（`--max-joints 1`）
2. 加上臂 + 肘关节 → 测 `pose` 命令
3. 加腕 + 夹爪（舵机 4）
4. 装到底盘板上，接驱动轮（舵机 5/6）
5. 整机 `home`，确认所有关节方向正确

**每加一个关节就测一次**，不要一次全装上再通电 —— 出问题时你分不清是哪个。

M1 验收：手动示教抓放 100g 物体，10 次成功 ≥ 8 次。
示教做法（还没有视觉）：

```bash
# 手动把臂摆到抓取位，读三个关节角度，记下来
./.venv/bin/python -m modkit.cli --port /dev/ttyUSB0 read --id 1
```

把这组角度写成"示教脚本"，回放即可。这就是最低成本的"机器人任务"。

## 第 6 步 · 让它自己走（M2，3 周）

- 驱动轮用**恒速模式**（寄存器 0x21 写 1），速度写 0x2E（带方向位）
- 里程计直接读轮子位置计数（`Robot.update_odom()`）
- 先做**开环**：给速度、跑 2 米、量偏差
- 再做**闭环**：编码器算实际速度，PID 修正

验收：直线 2m 偏差 < 5cm；原地转 90° 误差 < 3°。
不过关就别加视觉 —— **地基不稳，上面盖什么都会塌**。

---

## 第 7 步 · 看见并抓住（M3，4 周）

1. 相机装支架上，拍一张标定板（棋盘格），做**内参标定**
2. 相机固定在底盘上 → 做**手眼标定**（相机→base_link 的变换）
3. 颜色阈值找方块 → 算像素中心 → 反投影到桌面平面 → 得到 base_link 坐标
4. 逆解 → 抓

新手最容易错的两点：

- **忘了坐标系转换**（像素 → 相机 → base_link），结果抓空气
- **光照变了阈值就废**：先在固定灯光下调通，再加自动曝光/补光

验收：10 次抓取 ≥ 8 次。

## 第 8 步 · 任务闭环（M4）

把前面所有能力串成一个状态机：

```
IDLE → NAV_TO_A → SEEK（转头找方块）→ ALIGN → GRASP → LIFT
     → NAV_TO_B → PLACE → HOME → IDLE
                  ↘ 任一环节失败 → RECOVER（重试 1 次）→ IDLE
```

- 每个状态有**超时**（比如 SEEK 超过 20 秒就 RECOVER）
- 每个状态有**进入条件/退出条件**，写清楚，别靠"应该到了"
- 全部日志带时间戳，失败能回放

验收：任务 T1（见 [00-项目计划](00-项目计划.md) §1）5 次 ≥ 4 次。

## 第 9 步 · 以后怎么改（这才是长期价值）

### 9.1 改一个尺寸

```
改 cad/params.py 的一个变量 → 跑 build.py → 看自检是否全绿 → 重新导出 STL → 打印
```
**永远不要直接改 STL**（那是网格，改不动也改不对）。

### 9.2 加一个关节

1. `params.py` 加长度/限位
2. `parts.py` 复制一个模块函数，改尺寸
3. `build.py` 的干涉检查加一对（新关节 × 相邻件）
4. `kinematics.py` 的 `ArmGeometry` 加 `l3`，改 `forward/inverse`
5. 跑 `pytest`，往返测试会自动验证你改对没有

### 9.3 加一个传感器

1. 先写"假数据源"（像 `SimLink` 那样），让上层逻辑先跑通
2. 再写真驱动，保持接口一致
3. 加一条测试：假数据 → 期望行为

### 9.4 换主控（ESP32 → STM32/树莓派）

只改 `firmware/esp32/esp32_bus.h` 这一个文件（实现 `IHalfDuplexBus` 的 4 个方法），
`scs_frame` / `scs_servo` 一行不动。

## 第 10 步 · 每周节奏（建议）

| 时间 | 做什么 |
|---|---|
| 周一 30min | 定本周一个小目标（可验证的一句话） |
| 周三 2h | 动手；失败就记现象 |
| 周五 1h | 跑三套测试；写日志；更新 README 状态表 |
| 周日 30min | 复盘：这周哪个假设被推翻了？ |

**判断有没有进步的标准不是"机器人动了"，而是"测试多了一条 / 日志多了一条可复现的失败"。**
