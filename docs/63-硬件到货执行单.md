# 硬件到货执行单

> 这张表是“东西到了以后，按顺序把物理闸门从 0/5 推到 5/5”的现场清单。
> 原则：**先只读、再卸力、再单轴、再整机**；任何一步不过，停下来记录，不要跳步。
> 现在的物理状态是 **0/5**：没有采购、没有打印、没有装配、没有上电、没有标定。
> 按阶段生成的逐项清单/接线/验收见 [77 硬件准备包](77-硬件准备包.md)。

## 0. 开始前

### 0.1 工具

- 万用表（通断/电压/电流，最好有 10A 档）
- 可调电源（12V，限流 3A 起）或带保护的电池
- 绝缘垫、护目镜、扎带、耐高温胶带
- 内六角/十字螺丝刀、扭矩扳手（0.5–2 N·m）
- 卡尺、钢板尺、角度尺
- USB 转 TTL（1Mbps，3.3V/5V 电平确认）
- 手机/相机（拍证据）、标签纸

### 0.2 安全布置

1. 手臂下方垫软垫，桌面留出至少 300mm 半径的空旷区。
2. 主电开关放在手边，**手不离开**；第一次上电不要无人值守。
3. 先卸力，手动把臂摆到中间姿态，确认没有卡住线缆。
4. 电池先不接，用限流电源；限流从 2A 起，逐级放到 5A。
5. 任何焦味、冒烟、异响、舵机发热 → 立即断主电。

### 0.3 先跑离线

没有硬件也能把软件路径走一遍；**这不算物理通过**：

```bash
cd software
python -m modkit.cli --sim preflight --expect 1,2,3,4,5,6 --write-limits \
  --report ../records/preflight-sim.json
python -m modkit.cli --sim selftest --json ../records/selftest-sim.json
cd ..
make check-fast
```

预期：`预检：PASS`；selftest 6/6；测试全绿。仿真通过只说明代码路径通，不代表实物。

## 2. 逐日步骤

### D0 开箱与清点

- 按 [51 下单清单](51-下单清单.md) 和 [04 BOM](04-BOM.md) 清点：6 个舵机、电源/电池、
  USB-TTL、轮子、螺丝/轴承/铜套、线束、打印件。
- 每个舵机贴 ID 标签；先不要接线。
- 拍照记录外包装、序列号、缺件/破损。

**停止条件**：舵机型号/电压/ID 与订单不符；结构件断裂；缺少关键紧固件。

### D1 G0：尺寸、质量、空载电压

- 卡尺测关键孔距/连杆长度，和 `cad/params.py` 对照；偏差 >0.5mm 记下来。
- 称整机/臂/电池质量；和 809g 设计值对照。
- 限流电源 12.0V，限流 0.5A，空载测总电流；应在几十 mA 量级。
- 用万用表确认电源极性、保险通断。

**通过**：无短路；电压 11.8–12.2V；关键尺寸可装。  
**不过**：先改模型/支架，不要带着错尺寸上电。

### D2 打印与首件

- 按 [31 打印参数](31-打印参数.md) 和 [30 工序卡](30-工序卡.md) 打印。
- 首件重点：肩/肘关节座、夹爪、轮毂、底板；检查层间粘合、孔位、轴承配合。
- 试插定位销/螺丝；过紧就修孔，不要硬砸。

**通过**：手动试装能到位；关键孔不需要扩孔超过 0.3mm。  
**不过**：层裂/翘曲/孔偏 → 重打或改参数，不要用胶水糊。

### D3 机械装配

- 按 [05 装配手册](05-装配手册.md) 顺序；先不接线。
- 螺丝按工序卡扭矩，避免压裂 PETG；必要时加垫片。
- 手动走一遍肩/肘/夹爪全行程，确认线缆不被拉扯、夹爪不撞腕。

**通过**：全行程顺滑；断电后能手动回中；没有异响。  
**不过**：卡滞/刮线/夹爪偏心 → 停下来修，不要靠舵机硬顶。

### D4 电气与线束

- 按 [03 配电](03-配电与线束.md)、[26 线束](26-线束加工.md) 做线。
- 万用表通断：12V、GND、总线 A/B；确认没有电源-地短路。
- 每支路 2A 保险；主保险按 BOM；电解电容极性确认。
- 舵机 ID 先不要全插，先接 1 个。

**通过**：通断正确；绝缘无短路；保险可更换。  
**不过**：任何短路/反接 → 重做线，不要“上电试试”。

### D5 上电前检查（bring-up 第 1 步）

```bash
cd software
python -m modkit.cli bringup --action init --serial M1-2026-0001 --operator "你的名字"
python -m modkit.cli bringup --action record --step 1 --result pass \
  --evidence ../records/d5-precheck.jpg --note "极性/保险/急停/限流确认"
```

**通过**：人眼确认 + 照片；急停/断电手段可用。  
**不过**：不接线、不上电。

### D6 只读扫描（第 2 步）

```bash
python -m modkit.cli --port /dev/ttyUSB0 bringup --action check --expect 6 \
  | tee ../records/scan.txt
python -m modkit.cli bringup --action record --step 2 --result pass \
  --evidence ../records/scan.txt --note "6/6 在线，无故障位"
```

**通过**：6/6 在线，电压/温度合理，故障字节 0。  
**不过**：缺 ID/读失败/故障位 → 查线、ID、供电，不要继续使能。

### D7 预检 + 单轴低速（第 3 步前）

```bash
python -m modkit.cli --port /dev/ttyUSB0 preflight --expect 1,2,3,4,5,6 \
  --report ../records/preflight.json
```

- 只有 `预检：PASS` 才继续；先**不要**加 `--write-limits`，确认读数稳定。
- 用 `calib probe --id 1` 逐个读位置；手动把臂摆到中间，确认方向。
- 单轴测试用 `calib` 或最小动作，幅度 ≤5°，速度 ≤300，手放主电。
- 通过后：

```bash
python -m modkit.cli --port /dev/ttyUSB0 preflight --expect 1,2,3,4,5,6 \
  --write-limits --report ../records/preflight-limits.json
```

**通过**：预检 PASS；单轴动作方向正确、无异响、电流不突增。  
**不过**：超温/低压/故障/方向反 → 断主电，先修。

### D8 零位/方向/限位（第 3 步）

对每个轴，先手动摆到机械中位，再记录：

```bash
# 例：yaw 在 0° 时读 tick；--min/--max 用实测安全范围
python -m modkit.cli --port /dev/ttyUSB0 calib --action zero \
  --id 1 --name yaw --deg 0 --dir 1 --min -120 --max 120 \
  --save ../calibration.json
```

- 方向：手动 +5°，看反馈是 + 还是 -；反了就改 `--dir`。
- 限位：从安全范围向内找，**不要顶死**；留 3–5° 余量。
- 重复三个轴；夹爪用 0/1 开度确认 26.84/40mm。
- 验证：

```bash
python -m modkit.cli --port /dev/ttyUSB0 calib --action verify \
  --file ../calibration.json --tol 2
python -m modkit.cli --port /dev/ttyUSB0 preflight \
  --calibration ../calibration.json --expect 1,2,3,4,5,6 \
  --report ../records/preflight-cal.json
```

**通过**：方向正确；限位不顶死；`verify` 误差 ≤2°；预检用标定文件仍 PASS。  
**不过**：任何轴方向/零位不确定 → 不要整机动作。

### D9 回差与重复精度（第 4 步）

```bash
python -m modkit.cli --port /dev/ttyUSB0 backlash --action measure --id 1 --name yaw \
  --center 180 --span 10 --file ../backlash.json
python -m modkit.cli --port /dev/ttyUSB0 bench --action repeat --n 10 \
  --x 180 --y 0 --z 120 --csv ../bench-repeat.csv
```

**通过**：回差有记录；重复离散 ≤2mm（设计目标，实测可放宽但必须记录）。  
**不过**：回差突然变大/丢步 → 查机械间隙、螺丝、舵机温度。

### D10 轮子与里程计（第 6/7 步）

- 架空轮子先确认方向；落地后直线 2m，记录左右 tick。
- 原地转 90°，记录左右 tick。

```bash
python -m modkit.cli --port /dev/ttyUSB0 odomcal --action straight \
  --ticks <实测> --distance 2000 --file ../odomcal.json
python -m modkit.cli --port /dev/ttyUSB0 odomcal --action turn \
  --left-ticks <左> --right-ticks <右> --deg 90 --file ../odomcal.json
```

**通过**：2m 误差可接受（建议 ≤5%）；90° 误差 ≤5°。  
**不过**：轮子打滑/跑偏 → 查轮距、地面、轮胎。

### D11 首次整机动作（第 5 步）

- 先卸力手动摆到安全中间姿态；确认桌面/底座包络。
- 用查看器或脚本发**一个**小动作；手放主电；不要同时抓取。
- 记录电流/温度/声音；有异常立即卸力。

**通过**：动作平滑、无异响、无碰撞、急停有效。  
**不过**：任何碰撞/过流 → 停下来，回到 D3/D4。

### D12 抓放（第 8 步）

- 用 26.84–40mm 的已知物体；先空抓，再低速抓放。
- 10 次记录成功/失败；失败要写原因（滑、偏、撞、掉）。
- `qc` 记录 Q3 抓放数据。

**通过**：≥8/10；没有掉落/夹伤风险。  
**不过**：连续滑落 → 调夹持力/指面/位置，不要只加电流。

### D13 30min 烤机（第 11 步）

```bash
python -m modkit.cli --port /dev/ttyUSB0 bench --action burnin --minutes 30 \
  --cycle 2 --limit 55 --csv ../records/bench-burnin.csv
```

**通过**：无过温停机、无重启、无丢步；温度曲线可解释。  
**不过**：>55℃ 或漂移 → 降占空比/加散热/换舵机。

### D14 结论（第 9/10 步）

- `bringup --action status`：11 步有证据的 pass 数。
- `qc --action validate`：Q1/Q2/Q3 全过。
- 把 M1–M5 的证据路径写进 [28 生产就绪检查](28-生产就绪检查.md)。
- 只有全部有证据，才把物理闸门从 0/5 改到 5/5；**simulate 不算**。

## 3. 停止条件（任一即停）

- 焦味、冒烟、异常发热（>55℃ 或快速上升）
- 电压 <10.2V 或电流接近电源限流
- 舵机故障位非零、丢包持续、反馈不更新
- 关节顶死、线缆被拉、结构件裂纹
- 急停/断电无法立即生效
- 任何人员夹伤/惊吓

停下来先记录：时间、动作、现象、照片/视频、最后一条日志。不要“再试一次”。
