# v1.4.0 · 预硬件安全与调试验收

> 版本：v1.4.0（2026-10-25）  
> 范围：**不依赖实物**能完成的安全联锁、标定接入、离线几何检查、查看器预检与到货执行单。  
> 物理闸门：**仍为 0/5**。本版本不购买、不打印、不接线、不上电。

## 1. 这一版解决什么

v1.3 解决了“界面产品级”，但没有回答一个更基础的问题：

> 如果现在把硬件接上，软件会不会在关节越界、超温、低压、通信故障或姿态撞桌时仍然下发动作？

v1.4 的答案是：**在软件层能拦的都拦；拦不住的明确写出来。**

新增四条防线：

1. **Python 安全策略**：关节软限位、单步、温度/电压/故障/反馈新鲜度、转矩/电流/加速度。
2. **离线几何包络**：桌面、底座避让、深折叠、工作空间；逆解后先检查再下发。
3. **查看器 fail-closed 联锁**：连上真机后先预检；4 轴任一异常，`下发姿态` 直接拒绝。
4. **到货执行单**：D0–D14 的顺序、命令、通过标准、停止条件、证据清单。

## 4. 行为变化（升级必读）

1. **肘关节方向修正**：v1.3 查看器把肘角直接按 `2048 + deg/0.0879` 发，和运动学
   `2048 - deg/0.0879` 相反。v1.4 已统一为“肘角向内为负、舵机计数增加”。
   如果你之前用 v1.3 发过肘目标，请重新确认方向，不要沿用旧日志里的 tick。
2. **夹爪反馈映射**：v1.3 把夹爪当普通角度显示；v1.4 显示真实开口 mm。
3. **下发前会写限制**：查看器在使能/下发前写 0x30/0x1C/0x29；如果你的舵机固件
   不支持某个寄存器，先在单轴上确认，不要整机批量写。
4. **单步限制**：默认 yaw/肩 45°、肘 60°、夹爪 0.5；大姿态要分步，不是 bug。
5. **预检会拒绝**：超温/低压/故障/反馈过期/目标越界/跳变过大都会阻止；不要为了
   “先动一下”把阈值改大。

## 5. 边界（必须同时读）

- **不是功能安全**：没有安全 PLC、安全继电器、力矩传感、动态碰撞检测、SIL/PL。
- **不是实物验证**：所有参数仍是设计值/估计值；没有温升、堵转、摩擦、回差、电池曲线。
- **几何是粗包络**：圆柱底座 + 平面桌面 + 关节角条件，不是网格碰撞；夹爪/工件不参与。
- **标定文件不等于正确**：零位/方向/限位必须由人用实测确认；错误标定会让软限位更危险。
- **UI 确认不是联锁**：真正的拒绝在 `guardMotion` / `SafetyPolicy`；对话框只是交互提示。
- **不能用于人身安全场景**。

## 6. 已知缺口（按优先级）

1. 实物零位/方向/限位/回差/温升/堵转/电池 sag。
2. 动态碰撞与接触力限制（电流突变只能算间接）。
3. 夹爪 μ/夹持力/滑移/变形。
4. 模块接口插拔寿命、线缆弯折、螺丝扭矩。
5. 急停响应时间、独立安全回路、风险评估。

这些不是“再写一个 UI”能补的；需要 [63 到货执行单](63-硬件到货执行单.md) 的实测数据。

## 7. 结论

- 软件层：**能离线验证的安全路径已经接上，且有测试**。
- 物理层：**没有硬件，0/5 不变**。
- 下一步：按执行单到货后做 D0–D14；在 G6 标定和 G7 功能通过前，不要对外说“机器人能用了”。
