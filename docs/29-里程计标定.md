# 29 · 里程计标定

> 轮子说是 65mm，实际可能 64.2mm；轮距说是 150mm，装完可能 151.5mm。
> 这两个误差会让"直行 2 米"变成"斜着走 1.93 米"，而且**越走越偏**。

## 1. 什么时候做

- 新机第一次能走之后（G6 之后、G7 之前）；
- 换轮子 / 换底盘 / 拆过驱动舵机之后；
- 发现"走直线会偏"或"转 90° 实际转了 85°"。

## 2. 直线标定（轮径）

1. 地面贴两条标线，间距 **1000mm**（用卷尺量，别用步测）；
2. 机器人在起点，轮子贴线；
3. 记录左右轮 tick：`modkit --port /dev/ttyUSB0 read --id 5 --id 6`；
4. 让机器人直行到终点（速度慢一点，避免打滑），记录 tick；
5. 算 tick 增量，填进命令：

```bash
modkit odomcal --action straight --ticks 20000 --distance 1000 --file odomcal.json
```

输出会给出 `scale` 和修正后的轮半径。**打滑会让结果偏大**，所以：

- 地面干净、轮胎无灰；
- 速度 ≤150；
- 走 3 次取平均（scale 差 >2% 说明有打滑或轮子松）。

## 3. 转向标定（轮距）

1. 原地转 **90°**（地上贴一条参考线，转完对齐）；
2. 记录左右轮 tick 增量（一正一负）；
3. 填命令：

```bash
modkit odomcal --action turn --left-ticks -2360 --right-ticks 2360 --deg 90 --file odomcal.json
```

`turn_scale` 会修正有效轮距。转 3 次，取平均。

## 4. 验证

标定后再走 1m / 转 90°，里程计读数应满足：

| 项 | 允许误差 |
|---|---|
| 直行 1m | ±20mm（2%） |
| 转 90° | ±3° |
| 直行 3m | ±60mm（不累积放大） |

不满足 → 回到 §2，别急着上视觉。

## 5. 标定文件

`odomcal.json` 跟机器走（按序列号存 `odomcal-M1-2026-0001.json`），
内容包括修正后的 `wheel_r_mm`、`track_mm`、两个 scale。

上位机启动时读它：

```python
from modkit import odomcal, kinematics
cal = odomcal.OdomCal.load("odomcal-M1-2026-0001.json")
geom = cal.geometry()          # 直接喂给 update_odom
```

## 6. 为什么不用"理论值"

| 误差源 | 量级 | 后果（走 3m） |
|---|---|---|
| 轮径 -1mm | 1.5% | 偏 45mm |
| 轮距 +1.5mm | 1% | 转 90° 差 0.9° |
| 左右轮径差 0.3mm | 0.5% | 走 3m 偏 15mm 且航向漂 |

都不大，但**导航/抓取要求 ±10mm**，所以必须标。
