# 23 · 版本与兼容

> 硬件也会"版本漂移"。这篇定义：**什么算一次改版、旧件还能不能用、怎么查。**

## 1. 版本号怎么编

| 层级 | 格式 | 例子 | 什么时候变 |
|---|---|---|---|
| 硬件 | `M1-vX.Y` | `M1-v0.6` | 任何影响装配/尺寸的改动 |
| 固件 | git tag | `v0.6.0` | 协议/控制逻辑改动 |
| 上位机 | 同 git tag | `v0.6.0` | CLI/API 改动 |
| 图纸 | 页脚 `REV` | `M1 / v0.6` | 与硬件同步 |

规则：
- **只改文档/注释** → 不动硬件版本；
- **改 `cad/params.py` 里任何尺寸** → 硬件版本 +0.1，并重出图纸与 BOM；
- **改接口（孔位/舵机型号/电压）** → +1.0，并写兼容矩阵。

## 2. 兼容矩阵

| 版本 | 连杆厚 | 底盘 | 关节模块 | 夹爪 | 能否与上一版混装 |
|---|---|---|---|---|---|
| M1-v0.5 | 4 mm | 同 | 同 | 同 | — |
| **M1-v0.6** | **6 mm** | 对接孔 Ø3.6（其余 Ø3.4） | 同 | 同 | ⚠️ 与 v0.5 底盘混装时，旧板孔小 0.2mm，需扩孔或只换连杆 |

> v0.6 只改了连杆厚度（4→6mm），目的是把 200g 载荷挠度从 4.08mm 降到 1.21mm。
> 孔位、外形、装配顺序都没变，所以 **v0.5 的件可以只换连杆升级**。

## 3. 改版流程（照做就不会漏）

```bash
cd cad && ../.venv/bin/python build.py          # 1. 几何自检 85 项
         ../.venv/bin/python manufacture.py     # 2. 方向/悬垂/壁厚/时长
         ../.venv/bin/python verify_design.py   # 3. 力矩/刚度/公差/驱动
         ../.venv/bin/python cost.py            # 4. 成本是否可接受
         ../.venv/bin/python drawings.py        # 5. 重出 13 页图纸
cd .. && make -C firmware test && cd software && pytest   # 6. 固件/上位机
```

然后：更新 `CHANGELOG.md` → 在本文加一行兼容矩阵 → 打 tag → 发 Release（附新图纸/STEP）。

## 4. 怎么查一台机器是哪版

1. **看记录**：`records/M1-2026-0001.json` 里有 `firmware_version` 与标定指纹；
2. **看图纸页脚**：打印件上没标，但图纸 PDF 的 `REV` 对应批次；
3. **量一下**：连杆厚度 4mm = v0.5，6mm = v0.6（最快）；
4. **固件**：`modkit --port ... scan` 后看启动日志版本号。

## 5. BOM 版本

`hardware/bom.json` 随 git 走。采购时记下 commit：
`git rev-parse --short HEAD`，写进采购单，避免"按新价买了旧料"。

## 6. 兼容性判断原则

- **孔位不变 = 可混装**（螺栓能对上）
- **外形变了但孔位没变 = 可混装，性能按弱的算**
- **电气接口变了 = 不可混装**（必须整批换）
- **固件协议不变 = 新旧板可同一上位机**
