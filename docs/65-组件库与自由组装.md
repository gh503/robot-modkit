# 65 · 组件库与自由组装

> 状态：**v1.5.0 已实现**（软件/接口层）。物理闸门仍 **0/5**：没有采购、打印、
> 装配、上电或标定。本文里的 PASS 是"装配图在模型里自洽"，不是"实物已验证"。

## 65.1 为什么做这一层

M1 原来是一套固定的 3D 模型 + 一套固定的关节映射。想换一个夹爪、把相机抬高
100mm、或者只做一个两轮小车，就要改 CAD、改 BOM、改安全配置，容易漏。

组件库把机器人拆成**有明确端口和数据的模块**：

- 机械：20mm 网格、输出盘 4×M3、工具法兰；
- 电气：12V 总线、5V 逻辑、舵机总线 in/out；
- 数据：质量、成本、功率、关节限位/零位、工具载荷；
- 装配：谁接谁、接在哪个孔、转多少度，全部写进一个 JSON。

这样同一套模块可以拼出底盘、云台、机械臂、传感器塔；每个组合都能在买件前
生成 BOM、功率预算、重心/支撑检查和安全配置。

## 65.2 坐标、端口与"证据等级"

### 坐标

- 组件局部原点：**底部安装面中心**，+Z 朝组件"向上"。
- 端口 `frame` 是 4×4 刚体变换：位置 mm + 欧拉角 XYZ（度）。
- 装配时子组件端口与父端口**直接对齐**；`spin` 只绕端口 Z 轴转 90° 的整数倍。
- 网格端口 `grid=(宽, 深)` 表示可用孔阵范围；`at=[dx,dy]` 必须是 20mm 的整数倍。

### 端口类型

| 类型 | 用途 | 配对规则 |
|---|---|---|
| `mech.grid` | 20mm 孔阵面 | 任意两块网格面可接；靠 `at` 选孔 |
| `mech.disc` | 舵机输出盘/盘座 | 一公一母（或中性） |
| `mech.tool` | 工具法兰 | 一公一母 |
| `elec.bus` | 舵机总线 | `bus_out` 公 ↔ `bus_in` 母 |
| `elec.power` | 12V/5V 电源 | `power_out` 公 ↔ `power_in` 母 |
| `elec.data` | USB/I²C 等数据 | 仅做接口声明，不校验协议 |

### 证据等级（必须诚实）

- `validated`：复用 M1 现有 CAD/测试，或有明确实物依据；
- `preview`：有参数化几何/接口，但**未打印/未装配**；
- `concept`：只有质量/功率/接口估算，CAD 和实物都未验证。

`component.concept` 会在装配报告里产生警告；不能把 concept 当已验证。

## 65.4 装配 JSON

最小可运行例子：

```json
{
  "name": "demo",
  "payload_g": 0,
  "max_accel_m_s2": 0.5,
  "components": [
    {"id": "base", "type": "frame.chassis_240"},
    {"id": "yaw", "type": "joint.yaw", "parent": "base", "port": "top",
     "at": [20, 0], "servo_id": 1}
  ]
}
```

字段：

| 字段 | 必填 | 含义 |
|---|---|---|
| `name` | 否 | 报告/文件名 |
| `components[].id` | 是 | 实例唯一名 |
| `components[].type` | 是 | 注册表 ID |
| `components[].parent` | 根组件外必填 | 父实例 id |
| `components[].port` | 有父时必填 | 父端口名 |
| `components[].child_port` | 否 | 子端口，默认 `mount` |
| `components[].at` | 否 | 网格孔位 `[dx,dy]`，20mm 整数倍 |
| `components[].spin` | 否 | 绕端口 Z 轴 90° 的整数倍 |
| `components[].rot` | 否 | 端口对齐后的额外 XYZ 旋转（度） |
| `components[].pose` | 仅根 | 根组件 6 自由度位姿 |
| `components[].servo_id` | 否 | 显式总线 ID；否则按顺序分配 |
| `components[].joint` | 否 | 覆盖关节名/限位/方向/零位 |
| `components[].offboard` | 否 | 电源/电池离板，不参与几何/重心 |
| `payload_g` | 否 | 工具端载荷 |
| `max_accel_m_s2` | 否 | 稳定性余量设计值 |
| `strict` | 否 | 包围盒重叠升级为错误 |
| `ignore_collision` | 否 | 明确豁免的实例对，如 `[["yaw","pitch"]]` |

### 求解

对每个非根实例：

```text
world(child) = world(parent)
             · frame(parent_port)
             · T(at.x, at.y, 0)
             · Rz(spin)
             · Rxyz(rot)
             · inverse(frame(child_port))
```

然后检查端口类型/公母、网格范围/20mm、端口复用、环、根数量。

> 这套端口只表达**刚性连接**。关节转动后的碰撞/重心需要在运动学/仿真层
> 另算；`assembly` 检查的是**装配零位**。

## 65.5 校验规则

| 代码 | 级别 | 触发 |
|---|---|---|
| `type.unknown` | error | 组件类型不在注册表 |
| `root.count` | error | 机械根不是恰好 1 个 |
| `parent.unknown` | error | 父实例不存在 |
| `cycle` | error | 父链有环 |
| `port.kind` | error | 端口类型不同 |
| `port.gender` | error | 公母不匹配 |
| `port.offset` | error | 非网格端口给了 `at` 偏移 |
| `grid.range` | error | 孔位超出网格范围 |
| `grid.pitch` | error | 孔位不是 20mm 整数倍 |
| `port.reuse` | error | 同一孔位被两个实例占用 |
| `port.max` | error | 超过端口 `max_uses` |
| `spin` | error | `spin` 不是 90° 整数倍 |
| `servo.duplicate` | error | 舵机 ID 重复 |
| `controller.capacity` | error | 舵机数 > 控制器上限 |
| `joint.duplicate` | error | 位置关节名重复 |
| `joint.overload` | error | 静态力矩 > 额定 |
| `joint.margin` | warn | 静态力矩 > 额定的 50% |
| `payload.max` | error | 载荷 > 工具标称 |
| `power.planning` | error | 规划电流 > 电源 |
| `power.peak` | warn | 峰值电流 > 电源 |
| `stability.outside` | error | 重心在支撑多边形外 |
| `stability.margin` | warn | 重心边距 < 10mm |
| `collision.aabb` | warn/error | 非相邻组件包围盒重叠；`strict` 下为 error |
| `component.concept` | warn | 使用了 concept 级组件 |

### 质量/功率/静载的算法边界

- **质量/重心**：按组件 `bbox` 中心 × 质量；载荷按工具 `tip` 位置。
- **静载**：关节下游全部质量 × 到关节中心的**水平距离**，作为保守的弯曲力矩；
  不是关节轴线投影，也不含动力学/冲击。
- **稳定性**：支撑多边形 = 根组件 `support`（没有则用根 bbox 底面）；
  重心投影必须在多边形内；`tip_accel = 9.81 × 边距 / 重心高度`。
- **功率**：`规划 = 怠速 + 0.25 × (峰值-怠速)`；峰值只用于警告，不假设所有关节
  同时堵转。这个 0.25 是设计假设，不是实测。
- **碰撞**：世界 AABB，非相邻组件才查；**不是网格碰撞**。`ignore_collision`
  必须写清楚为什么豁免，不能拿来掩盖真实干涉。

## 65.7 命令

```bash
# 组件库
modkit components                         # 列表
modkit components --category joint        # 按类别
modkit components show joint.yaw          # 看端口/关节
modkit components check                   # 注册表自检
modkit components --json                  # 机器可读

# 装配
modkit assemble validate assemblies/m1.json
modkit assemble plan assemblies/m1.json --out cad/out/assemblies/m1
modkit assemble preview assemblies/m1.json --out cad/out/m1.svg
modkit assemble validate assemblies/m1.json --payload 100 --strict
```

`plan` 输出：

| 文件 | 内容 |
|---|---|
| `plan.json` | 求解后的实例/世界位置、问题、BOM、功率、稳定性、关节静载、安全配置 |
| `bom.csv` | 汇总 BOM（UTF-8 BOM，Excel 可直接开） |
| `assembly.md` | 人读报告 |
| `preview.svg` | 俯视/侧视 AABB 预览（不是渲染图） |
| `safety.json` | 直接给 v1.4 `SafetyPolicy` 的位置关节配置 |
| `calibration.template.json` | 给 `calib` 的空白模板；**未标定** |

## 65.8 和 v1.4 安全层怎么接

`plan` 生成的 `safety.json` 结构：

```json
{
  "robot": "modkit-m1-standard",
  "calibrated": false,
  "joints": {
    "elbow": {"servo_id": 3, "min": -150, "max": 5, "unit": "deg",
              "zero_ticks": 2048, "dir": -1, "ticks_per_unit": 11.377,
              "max_step": 60}
  }
}
```

可以直接：

```bash
modkit preflight --sim --policy cad/out/assemblies/m1/safety.json --expect 1,2,3,4,5,6
```

注意：

- `ticks_per_unit` 是关节单位→tick；夹爪是 `opening/DEG_PER_TICK`，不是普通角度。
- 模板里 `calibrated: false`；先按 [63 到货执行单](63-硬件到货执行单.md) 标定，
  再把 `calibration.json` 交给 preflight。**生成安全配置不等于标定过。**
- 示例的关节名/限位是设计值，不是实测回差/零位。

## 65.9 CAD

```bash
make components       # 注册表自检 + 6 个示例 plan/BOM/safety/SVG
make components-cad   # 36 个 STEP/STL + manifest.json（cad/out/components/）
```

`component_cad.py`：

- `plate/beam/chassis`：按注册表尺寸/网格开孔，包围盒误差 ≤1mm 才 PASS；
- `joint`：复用 `cad/parts.py` 的底板/盖板/输出盘；
- `wheel/caster/gripper`：导出参考体，**不冒充最终打印件**；
- 采购件/概念件：只导出参考盒，方便看空间。

CAD 输出是派生物，`cad/out/` 已 gitignore；manifest 可重建。

## 65.10 怎么加一个新组件

1. 在 `software/modkit/components.py` 用 `register(Component(...))` 定义：
   尺寸/包围盒/质量/成本/端口/BOM/功率/关节/工具/支撑面。
2. 端口 frame 遵守"原点在底部安装面中心、+Z 向上"。
3. 选证据等级：没有实物就写 `preview`/`concept`，不要写 `validated`。
4. 在 `cad/component_cad.py` 加 `cad` 映射（或标 `None`）。
5. 写一个 `assemblies/*.json` 示例；跑 `modkit components check` + `make components`。
6. 如果它影响安全/采购，更新 [02 接口规范](02-接口规范.md)、[04 BOM](04-BOM.md) 和
   [62 物理约束台账](62-物理约束台账.md)。

## 65.11 已知边界

- 只校验装配**零位**；关节运动后的碰撞、重心、线缆拉扯没算。
- 质量/成本是估算；M1 示例 1854g 与 [01 系统设计](01-系统设计.md) 约 2.2kg
  同量级，但口径含电源/夹具/线材，不能直接当采购重量或称重结果。
- 静载用水平力臂，所有关节同轴时会得到 0；它是保守上界，不是完整动力学。
- 碰撞是 AABB，不是网格；细长件斜放会误报/漏报。
- `offboard` 只把电源移出几何/重心，不改变"它必须被固定"的物理事实。
- **物理 0/5 不变**：没有采购/打印/装配/上电/标定；所有 PASS 都是模型层。
