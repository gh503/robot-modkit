# 68 · 预算优化器

> 状态：**v1.8.0 已实现**。在线入口：
> <https://gh503.github.io/robot-modkit/design.html> → BOM → 预算优化。

## 68.1 它解决什么

v1.7 的预算模式只回答"现在超了多少钱"。v1.8 开始回答：

> **在保持可装配、可校验的前提下，哪一步替换最省钱？**

它不是自动改设计，也不是"点一下降到 ¥1000"的魔法。它给出**单步候选**，
每个候选都重新走一遍浏览器求解/校验；只有 `validate().ok` 的候选才会显示，
并且必须由人点"应用"。

## 68.2 算法

```text
当前装配
  ├─ 结构候选：去掉肘关节（把末端工具直接装回父件）
  └─ 替换候选：换更小的标准件 / 缩短方梁 / 换小夹爪
        ↓
  逐个 clone → 修改 → A.validate()
        ↓
  只保留 ok 且 BOM 成本严格下降的候选
        ↓
  按省钱排序，最多 8 条
```

关键点：

- **每个候选都是完整装配**，不是只改一个字段；应用时直接替换 `state.assembly`。
- **不通过校验就丢弃**，不会把"省钱了但装不上"的候选展示出来。
- 代价 `saving` 按 **BOM 合计** 计算，不按组件 `cost_cny`；这是 v1.5 以来的统一口径。
- `risk` 只用于 UI 提示：`high` 改变构型/任务能力，`medium` 改变尺寸/视野，
  `low` 只换小工具。

## 68.4 例子：m1 → 两关节

`m1` 是 18 组件 / 4 个位置关节 / ¥1127：

```text
去掉 elbow、a3、fore，把 gripper 直接装到 upper/out
→ 15 组件 / 3 个位置关节 / ¥968
```

这就是 `m1_budget` 的结构。区别是：优化器从**当前设计**生成，名字会加 `-opt`，
`description` 会记录应用了哪条候选；`m1_budget` 是预设的固定文件。

`arm_4dof` 上同样的操作会连 `wrist` 一起移除（14→9 组件、¥869→¥562），
所以候选标题会明确写"及下游 wrist"，不会假装只少一个肘关节。

## 68.5 UI

- BOM 页底部 → **生成降本候选**；
- 候选卡显示：标题、省多少钱、代价、应用后的成本/组件数/关节数；
- 点 **应用** 后：
  - 替换装配、重新校验、重新生成剩余候选；
  - 名字加 `-opt`，描述记录来源候选；
  - 自动保存到 localStorage（和普通编辑一致）。
- 当前超预算时，提示"优先看高节省候选"；没有候选时明确说没有，
  不拿"换个更贵的件"凑数。

## 68.6 边界

- **单步**：一次只应用一个候选；没有组合搜索/全局最优，也不做多目标
  （成本/质量/刚度/任务能力）加权。
- **BOM 口径**：成本是组件库保守估算，不是供应商报价；线材/紧固件/运费未计。
- **校验子集**：AABB 粗碰撞、静载、质量/重心/功率；没有动力学、没有网格碰撞、
  没有运动后干涉。
- **任务能力**：`drop-elbow` 是能力裁剪，不是免费降本；UI 用 `high` 标出。
- **物理**：仍没有采购/打印/装配/上电/标定；**物理闸门 0/5**。
