# 44 · 硬件仿真（数字孪生）

> 目标：**先在不买硬件的情况下把软件调通**。不是"命令 35° 就显示 35°"的动画，
> 而是会掉压、会下垂、会打滑、会丢帧的假硬件。

## 1. 和旧 SimLink 的区别

| 能力 | `SimLink`（旧） | `HardwareSim`（新） |
|---|---|---|
| 舵机到位 | 写目标立刻跟随 | 转速/扭矩上限、PD、死区、回差 |
| 重力 | 无 | 肩/肘按连杆质量算力矩，扛不住会下垂 |
| 电池 | 固定 12.0V | 内阻 + 电流 → 掉压；低压切扭矩 |
| 温度 | 固定 32℃ | I²R 发热 + 散热；过温保护 |
| 轮子 | 理想积分 | 加速限制、打滑系数、4096 量化 |
| 总线 | 即时 | 延迟/丢帧可注入 |
| 时间 | 真实 sleep | **显式步进**，CI 确定性 |

代码：`software/modkit/hwsim.py`；场景：`sim/scenarios/*.json`；CLI：`modkit simrun`。

## 2. 模型

### 舵机

- 位置模式：`τ = kp·误差 − kd·速度`，限幅 ±2.94 N·m；
- 速度模式（轮子）：目标 LSB → deg/s，一阶加速；
- 死区 0.15°，回差 0.20°（输出 = 转子 − 方向×间隙/2）；
- 电流 ≈ |τ|/kt + 空载；温度 = I²R 发热 − 散热；
- 状态位：负载异常（0x20）、温度异常（0x04）、电压异常（0x01）。

### 电池

`V = OCV − I·R`，默认 12.2V / 0.12Ω；`V < 9.9V` 切所有扭矩并置电压位。
六舵机同时动会看到明显掉压。

### 底盘

差速积分 + `slip` 系数（0 正常，1 完全打滑）；轮子位置按 4096/圈量化，
里程计仍走 `0x38`。

## 3. 场景

```bash
modkit simrun --all sim/scenarios
modkit simrun --scenario sim/scenarios/nav_square.json
```

| 场景 | 验证什么 | 结果 |
|---|---|---|
| `servo_hold` | 带 0.2kg 负载到 210° 并保持 | 208.7°，12.12V |
| `low_battery` | 9.5V 电池触发保护 | 9.49V，状态位 0x01 |
| `slip` | 打滑时轮子转、车不走 | 位移 0mm |
| `weak_servo` | 0.05 N·m 舵机扛 1kg | 掉到 75.5°，负载位 0x20 |
| `nav_square` | **在物理仿真里跑闭环方形** | 5.9–7.8mm / 2.9°，16.6s |

`nav_square` 是关键：控制器、协议、里程计、轮子动力学全在环里，不是理想积分。

## 4. 怎么加场景

```json
{
  "name": "我的场景",
  "sim": {"payload_kg": 0.3, "battery": {"ocv": 11.5}, "slip": 0.2},
  "actions": [
    {"cmd": "torque", "sid": 2, "on": true},
    {"cmd": "goto", "sid": 2, "deg": 210, "speed": 500},
    {"cmd": "wait", "seconds": 1.5},
    {"cmd": "assert", "path": "joint.2", "value": 210, "tol": 2}
  ],
  "assert": [{"path": "voltage", "op": "gt", "value": 11.0}]
}
```

支持动作：`torque` / `goto` / `drive` / `stop` / `wait` / `set` / `nav` /
`nav_square` / `assert`。路径：`voltage`、`time`、`pose.x`、`joint.2`、
`servos.2.status/temp/current/pos`、`chassis.slip`。

## 5. 相机仿真

`camsim.py`：俯视针孔相机，按同一套投影生成 640×480 的桌面图，方块有顶面/侧面/影子/噪声，
`vision.detect_color` 直接能测。

```bash
modkit camsim --out cube.png --cube 200,0,40 --detect
# 检测中心 (478.1,239.5)px → 桌面 (200.3,-0.6)mm（真值 200,0）
```

**透视补偿**：看到的是 40mm 方块顶面，直接用 z=0 标定会偏 10mm；`Camera.table_calib(z_obj=40)`
把顶面像素反算到方块底面中心。这一步不做，抓取会整体偏一个方块高度。

## 6. 全栈场景：相机 → 检测 → 逆解 → 抓取

`mission_pick.json` 把整条链放进 `HardwareSim`：

1. 相机渲染出 40mm 方块；
2. `detect_color` 找质心；
3. `table_calib(40)` 转桌面坐标；
4. `plan_pick` 逆解，`Robot.move_pose` 走"上方 → 抓取 → 抬升"；
5. 夹爪闭合，任务状态机返回成功。

结果：**9.8s、mission True、抬升到 z=59mm**，全程电池 12.17V。

再把导航接进来（`mission_nav.json`）：机器人先从 (0,0) 开到 (100,0)，
相机看到世界坐标 (300,0) 的方块，检测点先转世界、再按当前偏航转到臂基座（约 (200,0)），
抓起后开到 (-150,0) 放下。

结果：**14.2s、两段导航 7.8mm/6.4mm、mission True、终点 -145mm**。

## 7. 故障注入与重试

| 故障 | 机制 | 结果 |
|---|---|---|
| 丢帧 5% | `drop_rate` | 不重试直接 `RuntimeError`；`RetryLink(retries=3)` 后方形照跑，终点 5mm 内 |
| 打滑 0.2 | `slip` | 里程计高估位移，方形偏差 >70mm（已知边界，见 §8） |
| 低压 9.5V | `battery.ocv` | 切扭矩、状态位 0x01 |
| 弱舵机 0.05N·m | `servo.rated_torque` | 1kg 负载下垂到 75°，负载位 0x20 |

`RetryLink` 只重试传输层错误，协议/校验错误不重试；统计 `errors`/`retried`。

## 8. 调试图

```bash
modkit simplot --scenario sim/scenarios/nav_square.json --out square.png
```

左边是俯视轨迹（起点/终点），右边是 J1–J3 关节角 + 电池电压。
每 20ms 采一帧，场景跑完一次性出图；不需要真实时间。

`nav_square` 的图能看到 4 条边、4 次转向，以及转向时电压的轻微下沉。
matplotlib 是可选依赖 `pip install -e "software[plot]"`。

## 8.5 抓取不再是"几何成功"

`mission` 在闭合夹爪后过一遍摩擦锥（`contact.py`）：`2μN ≥ m√(g²+a²)·1.5`。
默认参数能抓住；`μ=0.05` 的 `slippery_cube` 场景期望失败。详见 docs/47。

## 9. 外部定位：打滑的解法

纯里程计在 `slip=0.2` 时方形偏差 >70mm。给机器人贴一个**平放标记**（80×50 品红矩形 +
前向青色圆点），固定俯视相机以 10Hz 出图，`localize_marker` 用两个颜色质心算出
`(x, y, yaw)`：

```bash
modkit simrun --scenario sim/scenarios/nav_square_localized.json
```

结果：**打滑 0.2 下方形仍闭合，每边 5.7–8.6mm / 1.7–3.0°**（纯里程计是 >70mm）。
相机 160×120、10Hz 复用同一帧，21s 仿真约 4.6s 跑完。

这是"实验室固定相机"方案，不是野外定位；遮挡、光照、标定仍要真机验证。

## 10. 固件在环

`firmware/test/sim_firmware.cpp` 把**真实固件类**（`DriveTrain`、`PowerMonitor`、`Watchdog`）
接到一个仿真被控对象上，用 `make -C firmware test` 跑，不需要 ESP32：

| 场景 | 断言 |
|---|---|
| 速度闭环 100mm/s | 实测 100±5，左右轮一致 |
| 原地转 30°/s | 里程计偏航 30±5°，x/y 不漂 |
| 低压 10.5V→10.0V | 1s 进 Low（限速 50%），2s 进 Cutoff |
| 主机失联 | 200ms 看门狗超时 |
| 一次校验错 | 本拍返回 false，下一拍恢复 |

**这一步抓到两个真 bug**：

1. **速度单位不一致**：固件按 tick/s 解释 0x2E，上位机 `speedcal` 按 deg/s 标定，
   差 4096/360≈11.4 倍。已统一为 **1 LSB = speed_unit deg/s**，两边同一口径。
2. **计数回绕**：`int16_t(now-prev)` 在跨 0 时给出 −4095 的假倒退，速度环瞬间反向、
   里程计跳 200mm。改成 12 位最短路径后，原地转测试从 −117° 回到 −39°。

## 11. 还没做的

- **完整刚体接触**：没有碰撞/摩擦锥，抓取接触力还是近似；要这个得上 quench3d（docs/37）；
- **野外定位**：固定俯视相机能救打滑，但机器人一旦走出视野就需要车载相机/标记；
- **夹持接触**：抓取成功是"几何可达 + 夹爪闭合"的判定，没有接触力/滑移；
- **相机在机器人上**：目前是固定俯视，手眼标定还没进环；
- **参数辨识**：质量/惯量/内阻是估算，真机到位后要用实测替换；
- **实时性**：场景是快进，不是实时；接网页预览需要另外的时钟。
