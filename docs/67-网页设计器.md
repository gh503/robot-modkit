# 67 · 网页设计器（Studio）：自由装配、运动仿真与导出

> 状态：**v1.18.0 已实现**。在线入口：
> <https://gh503.github.io/robot-modkit/design.html>
>
> 它把 v1.5 的组件库/装配 JSON 直接接到浏览器：可以加件、换件、删件、
> 改孔位/关节限位/载荷，做**运动学示意**，导出设计 JSON、BOM、装配 STL、
> 2D SVG 和单件 STEP。物理闸门仍 **0/5**：没有采购、打印、装配、上电、标定。

## 67.1 为什么不是"再做一个 3D 查看器"

查看器（`web/index.html`）是固定 M1：`viewer.js` 按 `scene.js` 里的固定参数
建模型。它适合展示，不适合"换一个夹爪/加一节梁"。

设计器换了数据源：

```text
software/modkit/components.py       组件注册表（36 个，唯一真源）
            │
            ├─ tools/export_web_design.py
            │      ├─ web/data/components.js   （端口/质量/成本/关节/工具/STEP 路径）
            │      ├─ web/data/assemblies.js   （7 个预设装配）
            │      └─ web/models/*.step        （36 个预生成零件 STEP）
            │
            └─ assemblies/*.json               （装配图）
                       │
                       ▼
                web/assembly-core.js          浏览器端装配求解/校验
                       │
                web/budget-core.js            预算优化候选（复用校验）
                       │
          ┌────────────┼──────────────┐
          ▼            ▼              ▼
      three.js 场景   BOM/功率/重心   SVG/STL/JSON 导出
```

`web/assembly-core.js` 是 `software/modkit/assembly.py` 的**同语义子集**：
同样的端口配对、20mm 网格、`spin`、舵机 ID、BOM、功率、重心/支撑、
AABB 碰撞和关节静载。差异在本文 §67.7 写清楚。

## 67.2 三栏界面

打开 `design.html`：

- **左栏 · 组件库**：36 个组件按 9 类分组；搜索 ID/名称/类别；点组件添加
  到当前选中的父件。`concept` 件有橙色标记。
- **中栏 · 3D 场景**：左键旋转、右键平移、滚轮缩放；点模型选中实例。
  下方是位置关节滑杆和"播放运动 / 复位 / 速度"。
- **右栏 · 装配/校验/BOM/导出**：
  - 装配树：点节点选中，`✕` 删除子树；
  - 选中组件：父端口、子端口、`at`、`spin`、`rot`、舵机 ID、关节名/限位；
  - 方案名、工具载荷、`strict`（把 AABB 重叠升级为错误）；
  - 校验：总质量、BOM、规划电流、支撑余量、问题列表；
  - BOM：物料/数量/单价/小计；
  - 导出：见 §67.5。

顶部预设下拉框可切换 7 个示例：

| 预设 | 组件 | 位置关节 | 说明 |
|---|---:|---:|---|
| `m1_budget` | 15 | 3 | **预算版**：240 底盘 + 偏航/肩 + 固定上臂 + 40mm 夹爪，¥968，定点抓放 |
| `m1` | 18 | 4 | 240 底盘 + 3 关节 + 40mm 夹爪的**同轴塔式**验证装配 |
| `mini_rover` | 9 | 0 | 两轮 + 万向轮，电池 offboard |
| `pan_tilt` | 9 | 2 | 偏航 + 俯仰 + 相机 |
| `arm_4dof` | 14 | 5 | 4 关节 + 夹爪 |
| `wide_gripper` | 12 | 4 | 70mm 夹爪 + 100g 载荷 |
| `sensor_tower` | 8 | 0 | 传感器塔 |

> `m1` 是组件库的塔式装配，**不是**原 M1 CAD 的水平关节臂；不要互相冒充。

### 67.2.1 撤销/重做

- 顶部 `↶`/`↷`，或 `Ctrl+Z` / `Ctrl+Shift+Z`（`Ctrl+Y` 也可重做）；
- 历史保存 **装配快照**，最多 40 步，只在当前会话内有效，不写 localStorage；
- 加件/换件/删件/应用参数/应用优化候选/载入预设都会记一步；
- 撤销后继续编辑会截断 redo 分支，和常见编辑器一致。

### 67.2.2 优化报告

生成候选后，BOM 页的"导出报告"会下载 Markdown：当前 BOM、每条候选的
节省/应用后成本/组件/关节/风险/代价。和 CLI
`modkit assemble suggest --out report.md` 同用途。

### 67.2.3 规划达标

BOM 页的“规划达标”读取 `budget_cny`，最多走 4 步单步候选：

- 可达：列出每一步，点“应用全部”一次写入；记一步撤销；
- 不可达：显示最多到多少、还差多少，不显示“应用全部”；
- 规划是深度受限精确搜索：优先步数最少，其次成本最低；有 200 节点上限，
  超限会明确标记 `truncated`。失败通常意味着需要结构改动。

### 67.2.4 分享、离线与导入校验

- **分享链接**：顶部“分享”把当前装配编码进 URL hash（`#d=...`），复制到剪贴板；
  链接超过 60000 字符时拒绝，提示导出 JSON。打开链接会先做形状检查，再按普通装配求解。
- **3D 查看**：顶部“3D 查看”用当前装配打开只读 `view.html#d=...`；
  独立查看器见 [69-结构查看器](69-结构查看器.md)。
- **复制/粘贴/原地复制**：装配树上方三个按钮，或 `Ctrl+C` / `Ctrl+V` / `Ctrl+D`；
  复制的是整棵子树，粘贴到当前选中父件的可用机械端口。
- **拖拽导入**：把 `.json` 装配文件拖进页面，松手后替换当前设计。
- **3D 高亮**：选中件蓝色包围盒；错误/警告实例红/橙包围盒；点右侧问题条目可选中对应 3D 件。
- **浏览器冒烟**：`make web-smoke`；CI 的 `web-smoke` job 覆盖设计器/查看器/分享/离线，
  见 [70-浏览器冒烟测试](70-浏览器冒烟测试.md)。
- **离线壳**：`sw.js` 缓存 Studio 的 HTML/JS/CSS/组件数据；导航/脚本/样式
  network-first，图片/模型 stale-while-revalidate。断网后刷新仍可打开设计器
  （首次访问需在线）。脚本 network-first 是刻意的：发布后第一次刷新不会先拿旧 JS。
- **导入校验**：`MODKIT_ASSEMBLY.check()` 在 `validate()` 之前检查对象/数组、
  id 唯一、type 存在、parent 引用、at/rot/spin 数值、根组件恰好 1 个；
  导入和本地草稿都先过这一层，错误会显示前几条。**offboard 电源不算机械根**，
  所以 7 个预设（含 `sensor_tower` 的离板电源）都能导入。
- **分享快照**：载入后清掉地址栏 `#d=`，并抑制这一次自动保存；刷新不会把
  编辑重置回快照，也不会覆盖原有本地草稿。
- **本地草稿**：`localStorage` 存 `{schema, savedAt, assembly}`，兼容旧的裸装配格式；
  仍不持久化撤销历史或相机视角。
- **可访问性**：标签页支持 `←/→/Home/End`，带 `role=tab`/`aria-selected`；
  无 JS 时显示 `noscript` 提示；空格/焦点样式沿用系统。
- **离线版本**：`sw.js` 的 `CACHE` 必须和 `__version__` 同步，测试会拦住漂移。

## 67.3 添加/替换/删除

### 添加

1. 在装配树里选中父件（例如 `chassis`）。
2. 在左栏点一个组件（例如 `link.beam_100`）。
3. 设计器自动找**第一个兼容且未占满**的父端口；优先 `out`/`top`/`tool`，
   网格端口自动找最近的空孔位；然后重新求解。
4. 在右侧改 `at`/`spin`/`rot`、换父/子端口，点"应用参数"。

如果父件没有兼容端口，会提示；不会静默加一个错误连接。

### 替换

1. 选中要换的实例。
2. 点"替换组件"进入替换模式（左栏底部会变提示）。
3. 点新组件：保留父件/端口/孔位，只换 `type`，然后重新校验。

工具件统一提供**网格 + 输出盘双安装口**：

- `mount`：`mech.grid`，可直接装在方梁/夹爪网格上；
- `disc`：`mech.disc`，可装在舵机输出盘上；
- 因此 40mm 夹爪、70mm 夹爪、笔夹、真空吸盘可以在同一根臂上互换。

### 删除

选中后点"删除"。有子件时会二次确认并删除整棵子树；根件也可以删除
（删空后可从组件库重新加根件，或点"新建"）。

### 新建 / 导入 / 恢复

- **新建**：从 `frame.chassis_160` 开始一个空装配；
- **导入**：读 `design.json` 或 `assemblies/*.json`；
- **恢复**：读浏览器 `localStorage` 的上次草稿（只在本机，不上传）；
  页面启动时不会用预设覆盖草稿，点"恢复"才载入。

## 67.4 预算模式

v1.7 起，设计里有一个可编辑的 `budget_cny` 字段（默认 **¥1000**）：

- 校验面板顶部显示"预算余量"：`余 ¥32` 绿色，`超 ¥127` 红色；
- BOM 页显示"预算 ¥1000，余/超 ¥…"；
- HUD 也直接显示余/超，导出 JSON 会带上这个字段；
- 预设 `m1_budget` 是 **¥968** 的两关节定点抓放方案：`yaw` + `shoulder`
  + 固定 `upper` 梁 + 夹爪；它没有肘关节，不能改变臂展，只能抓放
  与肩关节同一半径上的两个站点。这是为 ¥1000 预算做的**有意识裁剪**，
  不是"三关节也能随便抓"。

预算字段只用于设计决策，**不改变 BOM 计算**，也不会让不合法的装配变合法；
最终报价仍按 BOM 行和供应商价格复核。

v1.8 起，BOM 页底部有"生成降本候选"：换小件/缩短方梁/去掉肘关节，
每条都重新校验，按 BOM 省钱排序。完整规则和边界见
[68 预算优化器](68-预算优化器.md)。

## 67.5 导出

| 按钮 | 产物 | 用途 |
|---|---|---|
| 装配 JSON | `modkit-<name>.json` | 交给 CLI 重新求解/生成安全配置；可再导入 |
| BOM CSV | `modkit-<name>.csv` | Excel/采购对账 |
| 装配 STL | `modkit-<name>.stl`（mm，二进制） | 进 CAD 做参考、干涉/打印检查 |
| 2D 预览 SVG | `modkit-<name>.svg` | 俯视 + 侧视、支撑多边形、组件标签 |
| 选中零件 STEP | `models/<id>.step` | 单件参数化 CAD |
| 全部零件 STEP ZIP | `modkit-<name>.step.zip` | 当前设计用到的所有零件 STEP |
| 复制 CLI 复现命令 | 剪贴板 | 把 JSON 放回 `assemblies/` 后跑完整计划 |

### 重要边界：STL 是网格，不是参数化装配

浏览器没有 OpenCascade/build123d，不能从 36 个 STEP 里做布尔并集再导出
装配 STEP。当前产物是：

- **装配 STL**：由网页里的简化几何合并，单位 mm；可导入 CAD 做空间/干涉参考，
  但不是供应商级 CAD，孔/倒角/公差不是精确几何；
- **单件 STEP**：36 个组件在构建仓库时由 `cad/component_cad.py` 预生成，
  STEP 本身是参数化 CAD 的交换格式，可编辑；
- **设计 JSON**：回到仓库后运行

  ```bash
  cd software
  ../.venv/bin/python -m modkit.cli assemble plan ../assemblies/<name>.json \
    --out ../cad/out/assemblies/<name>
  cd ..
  make components-cad
  ```

  再用 `cad/component_cad.py` 的参数重建零件。也就是说：
  **网页负责设计与验证；参数化 CAD 重建仍在仓库工具链。**

## 67.6 运动仿真

位置关节的滑杆直接改局部关节角，3D 子树绕关节中心 `joint.center` 旋转。
"播放运动"让所有位置关节在各自 `[min,max]` 内做正弦扫掠，夹爪在
`[0,1]` 内开合；轮式装配（没有位置关节）会转驱动轮。

这是**运动学示意**，不是动力学：

- 不计算重力、惯量、摩擦、回差、舵机跟踪误差；
- 不做运动过程中的网格碰撞/自碰撞；
- 不做抓取接触力；
- 速度滑杆只改视觉动画速度，不是真实舵机速度；
- 播放时不做安全限位拦截（限位只约束滑杆范围）；真机安全仍由
  `safety.json` + 固件 preflight 负责。

## 67.7 与 CLI 的差异（必须知道）

| 项 | 网页 `assembly-core.js` | CLI `assembly.py` |
|---|---|---|
| 端口/网格/公母 | 同语义 | 权威实现 |
| BOM/质量/功率 | 同口径 | 权威实现 |
| 重心/支撑/关节静载 | 有 | 有 |
| AABB 碰撞 | 有 | 有 |
| 复杂错误码 | 主要子集 | 完整 |
| 生成 `safety.json`/标定模板 | 只展示/导出 JSON | 写文件 |
| 参数化 STEP / 工程图 | 不生成 | `components-cad` / `cad` |
| 动力学/网格碰撞 | 无 | 也无 |

网页的校验结果用于**快速迭代**；发布/采购/上电前仍要跑：

```bash
make check-fast
cd software && PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 ../.venv/bin/python -m pytest -q
```

## 67.8 数据与缓存

- `web/data/components.js`、`web/data/assemblies.js` 是**生成物**，不要手改；
  改组件库后运行：

  ```bash
  .venv/bin/python tools/export_web_design.py
  ```

- `web/models/*.step` 也是生成/复制物；`make components-cad` 重新生成 STEP 后
  再跑上面的导出脚本。
- 设计草稿只存本机 `localStorage`；换浏览器/清缓存会消失。重要方案请导出 JSON。
- 页面是纯静态的，不需要后端；GitHub Pages 直接发布 `web/`。
