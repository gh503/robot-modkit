# 57 · 场景编辑器与回归基线

> 改一个断言要开编辑器、跑完、肉眼比数字，太慢。v1.1 给工作台加 JSON 编辑器，
> 给 CLI 加 `simdiff`：同一场景两次运行，位姿/电压/用时偏了就直接红。

## 1. 场景编辑器

工作台"场景回放"里：

1. 选一个场景 → **编辑**：`GET /api/scenario/source?name=...` 取原文；
2. 文本框里改 JSON，`Ctrl+Enter` 直接跑（`POST /api/scenario/run`，不落盘）；
3. **保存**：`POST /api/scenario/save`，文件名限制在 `sim/scenarios/` 下的
   `*.json`，拒绝 `../`、绝对路径、隐藏文件；
4. 保存后自动刷新场景列表。

后端校验：必须是含 `actions` 的对象；写文件前过 `scenario_path()`。

## 2. 回归基线

```bash
# 记录基线
modkit simrun --scenario sim/scenarios/nav_square.json --out baseline/
# 改代码后再跑
modkit simrun --scenario sim/scenarios/nav_square.json --out current/
# 比较
modkit simdiff --baseline baseline/nav_square.json --current current/nav_square.json
```

判据（可调）：

| 指标 | 默认容差 |
|---|---|
| 结果 ok | 必须一致 |
| 用时 | 相对 5% |
| 电压 | 0.05V |
| 终点位置 | 5mm |
| 终点偏航 | 2° |
| trace | ≥1 帧 |

输出 PASS 带 Δ；FAIL 列每条超差。CI 可把 `simdiff` 当门禁。

## 3. 测试

- HTTP：读源码、保存、直接运行、路径穿越拒绝；
- `simdiff`：相同通过；用时/电压/位姿漂移能抓；
- 编辑器不影响实时/回放状态机；空格在 textarea 里不触发运行。

## 4. 边界

- 没有语法高亮/自动补全，JSON 错误靠浏览器报错；
- 保存不做 schema 校验（只有 `actions` 存在性），坏场景会在运行时才报；
- 基线是"同一环境确定性结果"，跨机器/跨 Python 版本可能需放宽容差；
- 没有基线库/自动更新，基线文件要自己 commit。
