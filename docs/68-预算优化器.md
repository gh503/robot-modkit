# 68 · 预算优化器

> 状态：**v1.24.0 已实现**（优化器逻辑同 v1.21）。在线入口：
> <https://gh503.github.io/robot-modkit/design.html> → BOM → 预算优化。

## 68.1 它解决什么

v1.7 的预算模式只回答"现在超了多少钱"。v1.8 开始回答：

> **在保持可装配、可校验的前提下，哪一步替换最省钱？**

它不是自动改设计，也不是"点一下降到 ¥1000"的魔法。它给出**单步候选**，
每个候选都重新走一遍浏览器求解/校验；只有 `validate().ok` 的候选才会显示，
并且必须由人点"应用"。

## 68.2 算法

```text
当前装配
  ├─ 结构候选：去掉肘关节（把末端工具直接装回父件）
  └─ 替换候选：换更小的标准件 / 缩短方梁 / 换小夹爪
        ↓
  逐个 clone → 修改 → A.validate()
        ↓
  只保留 ok 且 BOM 成本严格下降的候选
        ↓
  标记 (成本, 重量) Pareto 非支配；按省钱排序（网页最多 24 条）
```

关键点：

- **每个候选都是完整装配**，不是只改一个字段；应用时直接替换 `state.assembly`。
- **不通过校验就丢弃**，不会把"省钱了但装不上"的候选展示出来。
- 代价 `saving` 按 **BOM 合计** 计算，不按组件 `cost_cny`；这是 v1.5 以来的统一口径。
- `risk` 只用于 UI 提示：`high` 改变构型/任务能力，`medium` 改变尺寸/视野，
  `low` 只换小工具。

## 68.4 例子：m1 → 两关节

`m1` 是 18 组件 / 4 个位置关节 / ¥1127：

```text
去掉 elbow、a3、fore，把 gripper 直接装到 upper/out
→ 15 组件 / 3 个位置关节 / ¥968
```

这就是 `m1_budget` 的结构。区别是：优化器从**当前设计**生成，名字会加 `-opt`，
`description` 会记录应用了哪条候选；`m1_budget` 是预设的固定文件。

`arm_4dof` 上同样的操作会连 `wrist` 一起移除（14→9 组件、¥869→¥562），
所以候选标题会明确写"及下游 wrist"，不会假装只少一个肘关节。

## 68.5 UI

- BOM 页底部 → **生成降本候选**；
- 候选卡显示：标题、省多少钱、代价、应用后的成本/组件数/关节数；
- 点 **应用** 后：
  - 替换装配、重新校验、重新生成剩余候选；
  - 名字加 `-opt`，描述记录来源候选；
  - 自动保存到 localStorage（和普通编辑一致）。
- 当前超预算时，提示"优先看高节省候选"；没有候选时明确说没有，
  不拿"换个更贵的件"凑数。
- **导出报告**：BOM 页"导出报告"下载 Markdown，内容与 CLI
  `modkit assemble suggest --out report.md` 同用途；如果已经规划，报告里会多一段
  “目标规划”（目标、步骤、可达/未达标、截断提示）。
- **截断提示**：搜索达到节点上限时，右侧规划卡和报告都会明说“可能不是全局最优”。

## 68.6 CLI

网页之外，`modkit assemble suggest` 提供同语义的单步候选：

```bash
# 列出候选
modkit assemble suggest assemblies/m1.json

# 只输出 JSON 元数据（不含完整 assembly），可直接 pipe 给 jq
modkit assemble suggest assemblies/m1.json --json

# 写 Markdown 报告
modkit assemble suggest assemblies/m1.json --out /tmp/budget.md

# 应用某个候选，写一个新装配 JSON
modkit assemble suggest assemblies/m1.json \
  --apply drop-elbow --out /tmp/m1-opt.json

# 再走正常校验/规划
modkit assemble validate /tmp/m1-opt.json
modkit assemble plan /tmp/m1-opt.json --out cad/out/m1-opt
```

`--apply` 写出的 JSON 名字自动加 `-opt`，描述记录来源候选；不会覆盖原文件。
Python 版本与 `web/budget-core.js` 使用相同的替换表和 BOM 口径，测试里对
`drop-elbow` 的 15 组件/3 关节/¥968 做交叉断言。

## 68.7 目标预算规划

单步候选不够时，可以给定目标预算，逐步应用“最大节省”候选：

```bash
modkit assemble suggest assemblies/m1.json --goal 1000
# 1 步可达 ¥968
modkit assemble suggest assemblies/m1.json --goal 900
# 2 步最多到 ¥964.4，仍差 ¥64.4；需要更大幅度改动
modkit assemble suggest assemblies/m1.json --goal 1000 \
  --apply-plan --out /tmp/m1-plan.json
# 写出的装配名加 -plan，再 validate/plan
```

- 网页 BOM 页有 **“规划达标”** 按钮；规划成功才显示“应用全部”，
  未达标会显示还差多少，不会给一个假“达标”。
- 网页“规划达标”默认最多 6 步；CLI `--max` 默认 8、Python 上限 12。
- 在候选树上做**深度受限穷举**：先满足约束，再找“步数最少”的达标路径，
  同一步数再选成本最低；不是只看每一步的局部最大节省。
- 网页/CLI 规划默认 **600 节点**上限（`--max-nodes` 可到 5000）；
  超限返回 `truncated=true` 和当前最优，不假装搜完。
- 每一步仍然重新校验；若当前装配已低于预算，规划返回空步骤，不写文件。

## 68.8 同价减重

默认候选只保留 BOM 成本严格下降的项，所以“换小底盘但价格相同”不会出现。
勾选 BOM 页的 **同价减重**，或 CLI 加 `--mass`，会额外保留
“成本不升、重量下降”的候选：

```bash
modkit assemble suggest assemblies/m1.json --mass
# [3] swap-frame.chassis_240-frame.chassis_160  省 ¥0.0 / 省重 80.0g
```

- m1 的 240→160 底盘：**成本 ¥1127.4 不变，重量 1853.8→1773.8g（-80g）**，
  18 组件/4 关节仍通过校验；支撑面变小，风险标 high。
- 候选卡显示“成本不升 · 省重 80g”，应用方式与普通候选相同。
- 规划 `plan()` 仍只按预算优化，不把减重当目标；同价减重是独立的探索模式。

## 68.9 Pareto 与约束

### Pareto 前沿

每个候选同时有 `cost` 与 `mass`。候选 A **支配** B，当且仅当：

- A 成本 ≤ B 成本，且 A 质量 ≤ B 质量；
- 至少一个严格更小。

`pareto=true` 表示没有别的候选支配它；`dominated_by` 记录支配者 id。
网页候选卡显示 **◆ Pareto** 徽标，可勾选“只看 Pareto”。默认仍按省钱排序，
Pareto 是“哪些取舍值得看”的辅助，不是新的自动选择。

> 注意：Pareto 只在**本次生成的候选集合**里比较，不是全局设计空间；
> 去掉肘关节常常同时更便宜更轻，会把很多单件替换支配掉。

### 约束

网页 BOM 页新增：

| 控件 | 含义 |
|---|---|
| 最少关节 | 位置关节数下限；例如 4 可阻止 `drop-elbow` |
| 最少组件 | 组件数下限 |
| 最大质量 g | 质量上限 |
| 最高风险 | 只允许 `low/medium/high` 中不超过该级别的步骤 |
| 只看 Pareto | 仅显示非支配候选 |

CLI 对应：

```bash
# 不允许去肘关节（至少 4 个位置关节）
modkit assemble suggest assemblies/m1.json --goal 1000 --min-joints 4
# 质量不超过 1500g；不可行时明确报违反
modkit assemble suggest assemblies/m1.json --goal 1000 --max-mass 1500
# 只看低风险步骤；更多搜索节点
modkit assemble suggest assemblies/m1.json --goal 1000 --max-risk low --max-nodes 1200
```

规划评分顺序：**约束满足 > 违反项少 > 预算达标 > 步数少 > 成本低**。
`plan()` 返回 `constraints`、`base_violations`、`violations`、`feasible`；
不可行时不会写 `--apply-plan`，网页也不会出现“应用全部”。

## 68.10 边界

- **单步候选**：候选卡仍是一次一个；组合路径由 `plan()` 搜索。
- **双目标而非全目标**：Pareto 只比较成本/质量；刚度、任务能力、可靠性没有量化权重。
- **BOM 口径**：成本是组件库保守估算，不是供应商报价；线材/紧固件/运费未计。
  真实到手价用 `assemble procure` 或 Studio BOM 页的“落地成本”，见 [76](76-分阶段构建与落地成本.md)。
- **校验子集**：AABB + 三角盒网格碰撞、静载+动载、质量/重心/功率；没有完整动力学、
  没有运动后连续干涉。
- **任务能力**：`drop-elbow` 是能力裁剪，不是免费降本；UI 用 `high` 标出。
- **物理**：仍没有采购/打印/装配/上电/标定；**物理闸门 0/5**。
