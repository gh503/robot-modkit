# 09 · 故障排查

> 排查顺序永远是：**电 → 线 → 协议 → 机械 → 算法**。
> 90% 的"算法不灵"最后都停在"线松了"。

---

## 1. 扫描不到舵机

| 检查 | 怎么做 | 正常值 |
|---|---|---|
| 舵机有电吗 | 万用表量舵机插头 V+ 与 GND | 11–12.6V |
| 共地了吗 | 量主控 GND 与舵机 GND 之间电阻 | < 1Ω |
| DATA 接对了吗 | 对照 [03-配电](03-配电与线束.md) 线序 | DATA 在中脚 |
| 波特率对吗 | 出厂 1Mbps；改过就用 115200 试 | `--baud 115200` |
| 方向脚对吗 | DIR 在接收态（低） | 摸舵机有轻微力矩 = 有电 |

**逐条排的脚本**：

```bash
./.venv/bin/python -m modkit.cli --port /dev/ttyUSB0 scan
./.venv/bin/python -m modkit.cli --port /dev/ttyUSB0 --baud 115200 scan
```

两个都不行 → 用示波器/逻辑分析仪看 DATA 线上有没有你发的字节（1Mbps，脉冲 1µs 宽）。

## 2. 扫描到但有舵机不应答 / ID 重复

| 现象 | 原因 | 处理 |
|---|---|---|
| 扫到 2 个但只接 3 个 | 中间那节线松，或该舵机 ID 重复 | 断开链，逐段接 |
| 某个 ID 时好时坏 | 插头氧化/半插 | 拔插 3 次，或换线 |
| 广播 PING 后总线"卡死" | 多舵机同时应答撞线 | **禁止广播 PING**，逐个扫 |

## 3. 不动 / 抖动 / 撞限位

| 现象 | 最可能原因 | 确认方法 |
|---|---|---|
| 完全不动，读位置也不变 | 扭矩没使能（0x28=0） | `read` 看位置，再 `set_torque(1)` |
| 抖动 ±3 计数 | 波特率/地环路/线太长 | 缩短线、加 1kΩ 上拉 |
| 一给指令就撞限位 | 方向反了 / 零位没标定 | 小角度 ±5° 试，确认方向 |
| 使能后自动往一边跑 | 目标位置写成了 0 或 4095 | 打印实际下发的帧 |
| 动到一半停住 | 过流/过温保护触发 | 读 `status` 位域与温度 |

```bash
./.venv/bin/python -m modkit.cli --port /dev/ttyUSB0 read --id 1
# 故障位: ['温度异常'] → 停机散热，检查是否堵转
```

## 4. 一动作就复位 / 电脑掉串口

| 原因 | 处理 |
|---|---|
| 电源功率不够（4 舵机同时动） | 降到一次动 1–2 个；换 10A；加 1000µF |
| 舵机地与主控地之间有压差 | 单点接地，主控电源从配电板取 |
| USB 线质量差 | 换带磁环的短 USB 线 |

## 5. 机械类

| 现象 | 原因 | 处理 |
|---|---|---|
| 螺钉拧不进 | 孔收缩 | Ø3.4 钻头手拧过一遍 |
| 铜螺母被拔出来 | 熔太浅/温度低 | 重新 250℃ 压到齐平，冷却 10s 再松手 |
| 输出盘打滑 | 花键啮合不足 | 量花键露出高度，改 `SERVO_SPLINE_H` 重打 |
| 关节晃动 | 齿轮虚位 + 打印件变形 | 正常 ≤ 0.5°；大了换金属舵盘 |
| 打印件裂 | 层间强度 | 改打印方向，让受力沿层内；换 PETG-CF |

## 6. 逆解报"到不了"

```bash
./.venv/bin/python -m modkit.cli --sim pose --x 999 --y 0 --z 90
# 到不了 (999, 0, 90)：距离 999.0mm 超出最大臂展 230.0mm
```

| 报错 | 含义 | 处理 |
|---|---|---|
| 超出最大臂展 | 目标太远 | 走近一点，或加长连杆 |
| 小于最小臂展 | 目标太近（在自己身上） | 目标至少离肩 40mm |
| 偏航超限 | 目标在身后 | 转底盘 |
| 肩角/肘角超限 | 姿态解不合法 | 换 `elbow_up`，或改限位 |

## 7. 视觉类（M3 之后）

| 现象 | 原因 | 处理 |
|---|---|---|
| 白天能抓，晚上抓偏 | 阈值随光照漂 | 固定补光；用 HSV + 自适应阈值 |
| 一直抓空气 | 手眼标定错/坐标系搞反 | 用已知点验证：把方块放固定位置，看算出的坐标差多少 |
| 检测框跳 | 反光/阴影 | 哑光目标物；加偏振片 |
| 相机延迟大 | USB2 带宽/分辨率过高 | 降到 640×480，MJPEG |

## 8. 任务逻辑类（M4 之后）

| 现象 | 原因 | 处理 |
|---|---|---|
| 卡在某个状态不出来 | 缺超时 | 每个状态都要有超时和退出条件 |
| 反复重试同一失败 | 错误恢复没分类 | 区分"可重试"（没看到目标）与"不可重试"（夹爪堵转） |
| 偶尔撞桌子 | 代价地图没更新/膨胀不够 | 障碍物膨胀 ≥ 机器人半径 |

## 9. 提交问题时的模板

```markdown
- 阶段：M1 / 关节 2
- 命令：`python -m modkit.cli --port /dev/ttyUSB0 pose --x 150 --y 0 --z 150`
- 期望：肘关节到 -90°，末端在 (150,0,150)
- 实际：肘到 -40° 就停，读回位置 2260
- 已排除：换过线、换过舵机、单独 read 正常
- 日志：<贴 10 行>
- 照片/视频：<链接>
```

**"已排除"那一栏是重点**：它决定了别人（或未来的你）要不要重复你做过的事。
