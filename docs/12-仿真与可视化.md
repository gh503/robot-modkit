# 12 · 仿真与可视化

> 目的：**在买零件之前，先把"它会怎么动"看清楚**；在焊线之前，先把控制环调明白。
> 所有几何参数从 `cad/params.py` 读，正解复用 `software/modkit/kinematics.py` ——
> 仿真和图纸、和上位机是同一份数学，不存在"仿真对、真机错"的漂移。

## 0. 在线实时查看（推荐）

**<https://gh503.github.io/robot-modkit/>**

浏览器里就能：拖动滑杆改偏航/肩/肘/夹爪 → 模型实时跟着动，右上角同步显示正解出来的指尖坐标；
点「播放抓取动画」看完整动作；四个视角按钮切换。

### 0.1 调试面板（v0.6.4 起）

Chrome/Edge + HTTPS/localhost 下，Web Serial 连真机（1Mbps），面板提供：

| 功能 | 说明 |
|---|---|
| 使能扭矩 / 卸力 | 写 `0x28`；**下发姿态前必须先使能**，否则舵机只记目标不动 |
| 下发姿态 | 4 轴目标位置（`0x2A`，速度 1000），自动补使能 |
| 急停卸力 | 4 轴 `0x28=0`，不依赖固件 |
| 跟随反馈 | 每 250ms 读 `0x38`（位置/速度/负载/电压/温度）+ `0x41`（故障位） |
| 调试表 | 目标 / 实际 / 误差 / 温度 / 电压；误差 >1.5° 黄、>5° 红；温度 ≥45℃ 黄、≥55℃ 红 |
| CSV 记录 | 勾选后把每帧写进 CSV，停止时下载（时间/关节/目标/实际/误差/温度/电压/负载/状态） |
| 演示数据 | `?demo` 或按钮：合成反馈走同一条渲染路径，没硬件也能看面板 |

### 0.2 它**不能**做什么（别指望）

- **不能替代固件调试**：没有轨迹规划、没有 PID 参数、没有电流环；
- **不能控轮子**（ID 5/6）和夹爪行程标定，只有 4 个关节角；
- **没有 IK**：只能拖关节角，不能在 3D 里点一个点让它自己解；
- **没有实时曲线**：只有表格和 CSV，振荡要看 CSV；
- **不能离线回放**：串口断了就没了；
- **不是安全设备**：急停是软件发帧，真急停请断主电。

本地打开（三选一）：

```bash
# A. 直接双击（file://，能用 3D，但 Web Serial 不可用）
xdg-open web/index.html

# B. 起个本地服务（推荐，Web Serial 需要 localhost 或 https）
cd web && python3 -m http.server 8765   # → http://localhost:8765

# C. 只截图/自动化：加 ?t=5 可跳到动画第 5 秒
```

为什么 Web Serial 必须 localhost/https：浏览器把串口当作敏感设备，`file://` 不算安全上下文。

## 1. 两套渲染器，各管一段

| | three.js（`shots.py`） | matplotlib（`draw.py`） |
|---|---|---|
| 用途 | 给人看的图：主图、四视图、爆炸图、动画 | 给 CI 看的图：不依赖浏览器，跑得快 |
| 依赖 | 本机 Chrome/Chromium | 只有 matplotlib |
| 质感 | 实体材质、实时阴影、描边、景深取景 | 线框+色块，能看懂但不好看 |
| 命令 | `make -C sim shots` | `make -C sim views` / `grasp` |

**为什么不用一套**：CI 机器上没有浏览器，也没必要为"好看"在 CI 里起 Chrome；
而给人看的图值得多花 2 分钟渲染。两套都从 `cad/params.py` 读尺寸，不会各画各的。

## 2. 它验证了什么（以及没验证什么）

**验证了**

- 几何一致性：轮子触地高度、臂展、夹爪开合范围都和 `params.py` 对得上
- 运动学正确性：动画里每一帧的末端位置都来自 `kinematics.forward()`，
  逆解失败会直接抛异常，不会"糊过去"
- 控制律有效性：同一套 PI 参数在 Python 仿真、C++ 单测里都要收敛
- 你的判断力：**能不能一眼看出"这动作不对劲"**

**没验证**

- 碰撞动力学（没有刚体求解器，不会告诉你撞到桌子会怎样）
- 舵机真实响应（只用了"一阶惯性 + 打滑 + 噪声"的简化模型）
- 结构强度（打印件层间强度、螺钉拉脱，只能实测）
- 视觉与导航（M3/M4 才有）

> 一句话：**它是"排除明显错误"的工具，不是"证明能用"的工具。**

## 3. 底盘仿真在讲什么

`sim/drive.py` 的判据（与 [06-调试与测试](06-调试与测试.md) G7 对齐）：

| 场景 | 开环 | 闭环 | 说明 |
|---|---|---|---|
| 直线 2m | 1768mm（−232） | **1993mm（−7）** | 打滑让开环少走 11%；PI 把它补回来 |
| 原地转 90° | 89.9°（0.9s） | 89.9°（0.5s） | 对称打滑不影响航向，但闭环快 44% |
| 转角 + 轮径标定差 2% | — | 88.3°（−1.7°） | **标定误差直接变成角度误差**，闭环补不了 |
| 1m 方形巡视 | 终点偏 401mm | 终点偏 8mm | 里程计曲线（虚线）演示内部漂移 |

最后一行是重点：**内环只能修"速度"，修不了"尺子不准"**。
所以 G7 里"速度寄存器标定"必须在上车第一件事做完。

## 4. 怎么改着玩

```bash
# 换抓取目标（改坐标就行，逆解失败会明确报错）
vim sim/anim_grasp.py     # build_sequence() 里的 kin.Pose(...)

# 换控制参数，看什么时候开始震荡
vim sim/drive.py          # KP, KI, Plant.tau, slip_left/right

# 换整机尺寸（改这里会同时影响 CAD 和仿真）
vim cad/params.py
```

想加新场景，照 `scenario_*` 的签名写一个函数：返回带 `err_mm`/`err_deg` 的 dict，
再在 `main()` 的 `rows` 里加一行，判据会自动跑。

## 5. 已知的坑

- **命名冲突**：`cad/render.py` 与 `sim/render.py` 同名时，`cad` 在 `sys.path` 前面会盖掉后者。
  现在 `sim` 里叫 `draw.py`，且 `model.py` 用 `append` 而不是 `insert(0)` 加路径。
- **中文字体**：matplotlib 默认字体没有中文，会画成方框。`sim/style.py` 里指定
  `Noto Sans CJK JP`（这台机器上有），换机器要改这一行。
- **GIF 体积**：121 帧约 1.7MB。要发给别人就压成 mp4：
  `ffmpeg -i out/arm_grasp.gif -vf "fps=12" out/arm_grasp.mp4`
