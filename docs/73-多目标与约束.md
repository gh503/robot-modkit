# 73 · 多目标 Pareto 与约束规划

> 状态：**v1.21.0 已实现**；v1.32 总测试 333。入口：BOM → 预算优化；CLI `assemble suggest --goal`。

## 73.1 为什么不是“加权总分”

预算优化器原来只按 BOM 省钱排序。问题是：

- “换小底盘”可能成本不变但减重 80g；
- “去掉肘关节”既省钱又减重，但任务能力下降；
- 给刚度/能力/价格硬凑一个权重，会得到一个看似精确、其实任意的分数。

v1.21 改成两个显式概念：

1. **Pareto 非支配**：只回答“还有没有在成本和质量上都更好的候选”；
2. **硬约束**：关节数、组件数、质量、风险级别由人给上下限，不满足就明说。

## 73.2 Pareto 规则

对候选集合中的 A、B：

```text
A 支配 B  ⇔  A.cost ≤ B.cost  且  A.mass ≤ B.mass
              且 (A.cost < B.cost 或 A.mass < B.mass)
```

- `pareto=true`：没有候选支配它；
- `dominated_by`：支配它的候选 id 列表；
- 网页显示 **◆ Pareto**，可勾选“只看 Pareto”；
- 报告表格用 `◆` 标记。

它只在**本次候选集合**内比较，不是全局设计空间；也不会自动选一个“最优解”。

## 73.3 约束语义

| 约束 | API/CLI | 作用点 |
|---|---|---|
| 最少位置关节 | `min_joints` / `--min-joints` | 装配校验结果 |
| 最少组件 | `min_components` / `--min-components` | 装配校验结果 |
| 最大质量 | `max_mass_g` / `--max-mass` | 装配校验结果 |
| 最高步骤风险 | `max_risk` / `--max-risk` | 规划路径的每一步 |

网页用 camelCase：`minJoints`、`minComponents`、`maxMass`、`maxRisk`。

规划评分顺序：

```text
约束满足 > 违反项少 > 预算达标 > 步数少 > 成本低
```

返回字段：

```json
{
  "feasible": false,
  "constraints": {"min_joints": 4},
  "base_violations": [],
  "violations": ["质量 1853.8g > 1500.0g"],
  "reached": false,
  "steps": []
}
```

`feasible=false` 时，网页不出现“应用全部”，CLI `--apply-plan` 拒绝写文件。

## 73.4 搜索规模

- 网页“规划达标”：6 步、600 节点；
- CLI `--max-nodes` 默认 600，最大 5000；
- Python `plan()` 默认 200 节点，最大 5000；
- 每个状态最多展开 16 个候选（单步候选表只有 8 个左右，实际受表限制）；
- 超限返回 `truncated=true` + 当前最优，不假装搜完。

## 73.5 例子

m1（18 组件 / 4 关节 / ¥1127.4 / 1853.8g）：

| 约束 | 结果 |
|---|---|
| 目标 ¥1000，无约束 | 1 步去肘关节 → ¥968，3 关节 |
| 目标 ¥1000，`min_joints=4` | 可行但不可达：¥1123.8，仍差 ¥123.8 |
| 目标 ¥1000，`max_mass=1500` | 不可行：当前 1853.8g > 1500g |
| 目标 ¥1000，`max_risk=low` | 安全候选省得很少，通常不可达 |

## 73.6 边界

- Pareto 只比较**成本/质量**；没有刚度、精度、可靠性、任务能力的量化。
- 约束只作用于候选/校验结果；不改变 CAD 参数，也不做连续优化。
- 节点上限意味着可能错过更优组合；`truncated` 会明说。
- 物理闸门仍 **0/5**。
