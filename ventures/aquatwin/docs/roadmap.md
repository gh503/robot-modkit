# AquaTwin 路线图：从报告到生产系统

> 原则：**先验证，再加功能**。每一阶段都有“不做什么”，避免把 demo 当产品。

## Phase 0 · MVP（0.1.0，已完成）

- 场景 schema + 校验 + 3 模板；
- 矩形覆盖/时间/能耗/过滤/成本/回收期；
- `report.md` / `dashboard.html` / `coverage.svg` / `metrics.json`；
- 9 项 pytest；零运行时依赖；可拆分独立仓库。

**不做**：Web 账号、支付、实时遥测、CFD、自动建图。

## Phase 1 · 试点（0–3 月）

**目标**：用 10–20 个真实池子证明误差可接受。

- 数据导入：CSV/JSON 实测（时间/能耗/压升/覆盖率）；
- 校准：`Cd`、泵效率、过滤压升系数；
- 报告加“预测 vs 实测”与置信区间；
- 批量模式：多池 CSV → 组合报告；
- 白标：logo/颜色/联系方式；
- 试点仪表盘：每池误差、异常、节省。

**Go 条件**：时间/能耗 MAPE ≤20%，覆盖率 ≤5pp，≥3 家愿意付费试点。

**不做**：自动控制机器人、在线支付、复杂形状。

## Phase 2 · 付费产品（3–9 月）

- Web 应用：项目/池/机器人/报告版本；
- 账户/权限/审计；
- API：`POST /studies`、`GET /reports/{id}`；
- CRM/工单集成（HubSpot/飞书/企微，按客户）；
- 订阅计费；
- 模型监控：预测偏差告警。

**商业化**：单次报告 → 服务商订阅 → OEM 白标。

## Phase 3 · 数据飞轮（9–18 月）

- 机器人遥测接入：时长、能耗、泵压、覆盖率、故障；
- 池型/污染/结果配对数据；
- 主动学习：挑最不确定的池子做标定；
- 行业基准报告（匿名聚合）；
- 相邻水域：养殖/蓄水池/灌溉，独立 schema 与验证。

**护城河**：数据 + 工作流 + 可解释模型，不是单点算法。

## Phase 4 · 生产级（18 月+，条件式）

- SOC2/等保/隐私合规（按市场）；
- 高可用/多租户/灾备；
- 现场安全/责任保险；
- 硬件伙伴联合方案；
- 开放 API/市场。

> 时间/团队/资金未定；这是能力路线，不是承诺。

## 技术债与决策

| 决策 | 现在 | 触发升级 |
|---|---|---|
| 纯 Python/无依赖 | ✅ | 需要 Web/并发 |
| 矩形覆盖 | ✅ | 客户 >30% 非矩形 |
| 固定 `Cd`/泵效率 | ✅ | 实测误差 >20% |
| 无数据库 | ✅ | 多用户/版本 |
| 单体 CLI | ✅ | API/队列 |
| 无 CFD | ✅ | 需要局部流场/过滤细节 |

## 关键指标

- 产品：报告生成时间、场景覆盖、误差、续费；
- 商业：付费客户、ARPU、CAC、回收期、留存；
- 技术：测试、模型版本、数据完整率、异常率；
- 安全：事故/隐私事件（目标 0）。
